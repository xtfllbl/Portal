# Paywizard Billing · 本地整理插件

**状态：v1.1.0 已在 Figma 桌面端生成 30 个可编辑画板，结构错误为 0、字体完整；三个验证 PNG 已完成重点视觉核对，全部状态的最终视觉验收待完成。**

此插件通过 Figma 官方 Plugin API 操作当前文件，不调用官方 MCP，不访问网络。源画板均保留；整理结果在新增画布 `Billing · Local handoff · 2026-09-20` 中生成。

## 导入与验证

1. 在 Figma 桌面版打开 [现有初稿](https://www.figma.com/design/jj3xBSZtky2muuHu2SBoH4)。如希望隔离整个文件，可先 Duplicate；插件自身也会新增副本画布，不修改源画板。
2. 菜单 **Plugins → Development → Import plugin from manifest…**，选择本目录的 `manifest.json`。
3. 菜单 **Plugins → Development → Paywizard Billing · Local Handoff**，运行插件。首次自动检查 30 个源画板、日期框数量及字体；失败时只报告原因，不创建画板。
4. 点击 **生成三个验证画板**。在下拉框分别选择 `41-03`、`44-07`、`44-10`，点击 **查看 / 导出 PNG**，核对日期、遮罩层级、邮件内容和字体。
5. 三个验证画板通过视觉检查后，点击 **整理全部 30 个画板**，再下载检查报告。30/30 且结构错误为 0 只是结构检查结果，仍须逐页视觉核对。

## 处理内容

- 按清单顺序补齐原生日期框文字与日历标识，避免依赖捕获后可能变化的绝对宽度。
- 对捕获遗漏的空筛选日期框，在原有 Date Range 容器中按 HTML 尺寸补齐；续期弹窗中的已填写日期独立匹配，不与空筛选框混淆。缺少已填写日期或无法识别容器时仍停止。
- 恢复弹窗的 40% 黑色遮罩，并将弹窗放到固定表头之上。
- 将已经捕获的收据原生图层嵌入邮件查看器，保留正文的滚动区域。
- 四个页面 Section、30 个编号画板及可点击的索引；保留 HTML 来源、日期、Git 版本和状态说明。
- 从现有导航生成三个本地共享组件，不引入外部设计系统或改变页面视觉风格。
- 导出画板 PNG 和包含最终节点 ID、字体、可编辑文字数量、日期框数量及检查结果的 JSON。

## 继续与失败处理

- 同一副本画布中已经生成的画板会跳过，正常完成后的重复执行不会再生成 30 份副本。
- 失败的画板会标注 `INCOMPLETE`，不会被当作已完成画板。原始捕获不受影响。
- 缺少字体时，报告会列出名称；不自动用其他字体替换。
- 源文件节点 ID 不匹配时停止，避免在错误的文件中生成设计。
- 收据使用 Arial；桌面端必须可用。主页面使用 Poppins、Material Symbols Rounded；日期占位使用 Noto Sans SC。

`engine.js` 是插件逻辑，`code.js` 是可直接运行的打包文件，`build.py` 从导出清单重新生成打包文件。不需要 npm install。

## v1.1.0 更新方式

使用已经导入的本目录插件时，无需重新导入 manifest。关闭正在运行的插件，再从 Plugins → Development 重新运行，标题应显示 `v1.1.0`。自动检查通过后先生成三个验证画板。若此前将插件文件复制到其他目录，需同步更新该副本的 `code.js` 和 `ui.html`。

原始错误报告显示：42-02 和全部 44 状态共 11 项日期数量错误；它们恰好缺少 22 个空日期输入，所有已填写日期都在。`fixtures/desktop-date-fields.json` 保留该报告中的节点和日期数量，用于回归测试。错误报告的 `changes` 及 `output` 均为空，没有生成或修改交付画板。
