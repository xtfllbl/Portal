## 用户已明确的目标

- 面向无人值守自助机业务，提供每台终端每天在线情况的可视化概览，类似 Uptime Matrix。
- 用户未启用告警功能时，仍需要查看这份在线历史。
- 引入可自定义的 Operating Hours，支持一周中不同日期采用不同安排，包括周末差异。
- Operating Hours 需要为后续增强现有告警配置提供基础。

## 第一轮已确认决策

用户答复：Q2「只需要统计 Payment Service」；其他三项接受建议。

| 问题 | 确认结果 |
| --- | --- |
| Q1 使用者与访问范围 | 同时服务商户自查及服务商、代理、Paywizard 运维巡检；沿用现有终端访问范围，无需先创建告警规则。营业时间的具体编辑权限尚待细化。 |
| Q2 在线口径 | 仅统计 Payment Service，不增加设备连接指标或切换；指标不代表整机正常出货或交易必定成功。 |
| Q3 时间表归属 | 门店默认时间表，终端可单独覆盖，也可恢复跟随门店；星期一至星期日可分别安排。时间表作为独立配置，供矩阵和后续告警使用。 |
| Q4 可视化结构 | 首屏为「终端 × 日期」矩阵，点击某一天展开该终端当天的时间轴。具体日期跨度、颜色及在线率算法尚未确认。 |

共同领域边界记录于 [ADR 0010](../../adr/0010-independent-payment-service-uptime-and-operating-hours.md)。本轮确认不等于批准后续建议、生产接入或立即改变现有告警行为。

## 第二轮已确认决策

用户答复「ok」，接受 Q5–Q10 的建议。

| 问题 | 确认结果 |
| --- | --- |
| Q5 在线率考核范围 | 仅统计已发生的营业时间；08:00–20:00 营业且营业内始终在线时，当日为 100%，非营业关机不扣分。当天只统计到当前时刻；详情保留全天状态并标记非营业时间。 |
| Q6 数据缺失 | Online、Offline、Unknown 分开；没有告警不代表在线。缺失数据需明确显示统计不完整，不能显示成全天正常；非营业时间作为独立时间标记。存在 Unknown 时百分比的具体展示仍待下一轮决定。 |
| Q7 时间表能力 | 一周七天分别选择全天营业、休息或自定义；每天支持多个时段及跨夜；指定日期可覆盖每周安排；未配置时默认为 24 小时营业，界面明确显示安排。 |
| Q8 时区与日期 | 保存地区时区，不随查看者时区变化；按该时区的自然日统计。周五 22:00–周六 02:00 的营业时长分别计入周五与周六，各两小时。 |
| Q9 历史变更 | 修改仅从生效时刻往后影响统计；历史使用当时有效的营业时间。门店修改仅影响跟随门店的终端，不覆盖终端独立配置。 |
| Q10 本期边界 | 本期交付矩阵与共享营业时间配置，现有告警保持当前规则。后续再定义跟随 Operating Hours、跨窗口累计、通知和旧规则兼容；本期不修改这些告警行为。 |

历史解释规则记录于 [ADR 0011](../../adr/0011-preserve-effective-operating-hours-for-uptime-history.md)。保留历史时间表不等于假定已经存在真实遥测，也不表示禁止修正错误观测数据；数据修正政策尚未定义。

## 第三轮已确认决策

用户修正 Q12：「默认最近 7 天」「历史保留 3 个月」；其余建议接受。下表为修正后的有效决策，原先默认 30 天及保留 12 个月的提案已被替代。

| 问题 | 确认结果 |
| --- | --- |
| Q11 日格与不完整统计 | 营业内全程已知在线为绿色；任意已确认离线都标红，不受告警阈值影响；Unknown 用斜纹标记，可叠加在有离线的日格上，不覆盖已知离线。含 Unknown 时不展示单一在线率，详情分列在线、离线、未知时长；休息日灰色且不显示百分比，尚未开始的营业时间不按数据缺失处理。 |
| Q12 日期范围与历史保留 | 默认最近 7 天，优先保证图形化可读性；历史保留 3 个月，可在保留范围内查看历史日期。原提案中的其他日期范围切换不改变 7 天默认首屏；移动端固定终端标识并可横向查看日期。这是产品目标，不是现有后端能力。 |
| Q13 页面入口与巡检操作 | Device Management 下增加 Uptime Matrix；单终端页提供该终端入口。总览支持权限内组织、门店、终端筛选及只看离线/数据缺失；默认有离线、仅数据缺失、正常分组，离线组内按所选期间营业内离线累计时长降序。日格打开详情抽屉，展示当天时间表、时区、在线/离线/未知时长及全天时间轴。 |
| Q14 编辑入口与权限 | 可查看终端历史不自动获得编辑权限；需有管理对应 Store 或 Terminal 的权限。矩阵提供 Operating Hours 管理入口，单终端提供自身配置入口；Store 用户可直接管理当前 Store，无需访问 Merchant 页面。编辑 Store 时间表时列明受影响的跟随终端数量；单台覆盖、恢复跟随均保留审计。权限为拟新增的生产产品要求，不能冒充现有原型已实现权限。 |
| Q15 终端覆盖边界 | 终端切换自定义后，周计划、特殊日期和时区作为完整独立时间表，不继续继承门店局部修改；恢复跟随后使用门店当前有效配置。门店时间表修改作为本期批量影响入口，不另外引入跨门店批量覆盖或可复用模板库。 |
| Q16 历史的终端标识 | 矩阵一行按物理支付终端 S/N 识别，不跟随 TCI 逻辑配置把不同设备的历史拼成一行；更换设备后新旧 S/N 分开保留记录。归属变化后的历史可见性及历史起点需在此项确认后展开。 |

物理终端身份边界记录于 [ADR 0012](../../adr/0012-identify-uptime-history-by-physical-terminal.md)。完整终端时间表覆盖的取舍补入 ADR 0010。

## 第四轮已确认决策

用户修正 Q18：刚接入终端从接入当天开始展示，之前日期不展示；修正 Q20：不需要自动刷新。其他建议接受，包括 Q21 的原型与规格交付。

| 问题 | 确认结果 |
| --- | --- |
| Q17 换店后的历史与配置 | 历史记录按发生时的 Store 归属隔离，并以查看者当前可访问的 Store 范围授权。原 Store 可查看归属期间的历史，新 Store 不获得加入前的历史；有权访问两店的上级可查看双方范围。解绑后历史仍按原归属保留至 3 个月期限；换到不同 Store 后默认跟随新 Store 时间表，旧终端覆盖仅保留用于历史解释，不自动带入新店。 |
| Q18 历史起点与回补 | 终端直接从接入当天开始展示，之前日期不展示，不增加「未纳入统计」格。接入当天只计入接入时刻后的有效营业时间；纳入后无足够观测的应统计时段才是 Unknown。允许权威数据在保留范围内补齐或纠正历史，并显示更新时间；回补使用当时有效的营业时间，不通过修改营业时间重写旧统计。当前原型没有可验证的生产历史，不猜测真实起点或补造真实观测。 |
| Q19 日期例外与跨夜 | 指定日期的例外配置优先于该当地日期的全部常规营业片段，包括前一天跨夜延续的片段。例如周五 22:00–周六 02:00，但该周六明确配置整日休息，则周六 00:00–02:00 不计营业。编辑器展示最终有效时段预览，时间输入无效、重复或重叠时阻止保存并指出冲突；取消不保存。 |
| Q20 刷新体验 | 不自动刷新、不轮询；提供手动 Refresh 和最近数据更新时间。请求失败保留上次成功结果并明确提示失败，不将请求失败直接解释为终端离线；不会把旧 Online 无限延展成最新在线状态，数据新鲜度与状态判定依赖权威 Payment Service 契约。历史补齐可通过手动刷新更新。 |
| Q21 下一步交付 | 本轮确认后，按所有已确认规则先完成本仓库可交互原型与完整研发规格；原型用明确标识的模拟数据覆盖三个月内的代表情况，营业时间配置及版本可保存并在刷新后保留。真实遥测、生产授权和服务端存储作为独立对接项，不宣称已经接通；本期不自动加入导出。 |

## 决策树

Q1–Q21 已确认，本期决策树已收敛。以下总结有效结论；生产接入事实缺口写入研发规格，不作为原型工作的阻塞项。

1. **使用者与访问范围**：沿用资源范围，查看与编辑权限分离；历史按发生时 Store 和查看者当前 Store 权限交集授权；换店恢复跟随新 Store，解绑保留已归属历史。
2. **“在线”的业务口径**：仅 Payment Service，营业内已发生时段，原始 Unknown 独立保留、应上报缺报计入不在线，采集故障不返回单一百分比，实际短暂离线始终保留，S/N 身份；保留 3 个月，从接入当天开始展示，允许权威观测回补；仅手动刷新。生产采集契约仍需对接。
3. **Operating Hours 的配置归属**：门店继承与完整终端覆盖、周计划多时段、跨夜、例外日期、地区时区、历史版本及通过门店修改批量生效；日期例外覆盖跨夜延续，冲突输入阻止保存并定位错误。
4. **首屏需要回答的问题与矩阵形态**：默认 7 天矩阵、日内抽屉、字段、颜色、排序和移动端阅读已确认；具体视觉实现遵守仓库统一门户样式，无额外副标题、同一操作区按钮等高。导出没有明确需求，不自动加入本期。
5. **Operating Hours 与告警的关系**：已确认本期保持既有告警行为；跟随营业时间、旧规则兼容、跨窗口阈值累计及窗口外事件/通知整体延后，不作为本期实现的未决阻塞项。
