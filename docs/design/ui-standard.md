# Portal 原型 UI 设计规范

## 目的与边界

让新增、改动页面具有一致的外观与交互，并让研发能将原型控件对应到 PrimeVue v4 组件。规范适用于静态 HTML/CSS/JavaScript 原型；设计对齐不代表已使用 PrimeVue，也不要求安装 Vue、PrimeVue、shadcn/vue 或迁移架构。技术迁移不属于当前或后续目标。

2026-09-20 确认：PrimeVue v4 为主，shadcn/vue 与 Figma 社区稿为辅；保留现有紧凑规格；新页面与修改区域逐步规范；允许组合和自定义组件。无需为了应用本规范批量改造未涉及的页面。

## 依据与冲突处理

按以下顺序处理设计依据：

1. 用户最新明确要求，以及该功能已确认的业务规则和交互约定。
2. 项目规范：根目录 [AGENTS.md](../../AGENTS.md) 的 UI 规则、本规范，以及相关功能设计文档。
3. PrimeVue **v4** 官方组件文档：组件用途、结构、能力、状态与键盘交互的主要参考。
4. PrimeOne v4 Figma UI Kit：与 PrimeVue 配套的视觉参考。
5. shadcn/vue 文档及 Figma 社区设计稿：补充布局、信息组织与交互思路。

现有页面用于查找共享实现和已确认样式；偶然存在的不一致不自动成为规范。外部示例不覆盖项目业务规则、紧凑尺寸或已确认的图标体系。PrimeVue 的组件行为与主题样式可分别参考；采用其组件模式不等于照搬演示页配色、字体或留白。

涉及具体组件时查阅相应 v4 文档。研发实际使用的小版本、主题及自定义能力如已提供，以其为核对依据；尚未提供时，不宣称与研发实现完全一致。社区稿不作为组件 API 或能力的证明；PrimeOne 与代码组件也不保证同步更新。

## 每次设计或改页的执行顺序

1. **定位页面和共享实现。** 阅读目标页面、同类页面及相关功能设计文档，确认已有侧栏、顶栏、样式、脚本和可复用交互。仅做 UI 调整时维持业务规则、数据和流程。
2. **选择组件模式。** 为本次新增或实质调整的控件查找下表及官方参考，明确采用标准模式、组合模式还是自定义模式。沿用且未改变行为的控件无需重复研究。
3. **确定样式和状态。** 使用项目已有共享样式或变量，核对相关的选中、禁用、加载、空数据、错误与焦点行为；不因官方示例存在某项能力而给页面增加无关功能。
4. **在现有架构中实现。** 使用现有 HTML/CSS/JavaScript 及共享模块实现对应模式。参考资料不可访问时，沿用已验证的项目模式，并在交付说明中写明尚未核实的能力，避免凭截图推断。
5. **验收并说明。** 打开实际修改页面完成桌面视觉和交互核查。交付时简述本次关键组件映射、自定义原因和验证结果；说明留在开发文档或交付回复中，产品界面只呈现用户需要的内容。

## 常用组件映射

下表是设计选型入口，不是新增功能清单，也不是直接引入组件库的指令。组件的具体能力与配置以对应 v4 文档为准。

| 页面需求 | PrimeVue v4 参考 | 项目设计要点 |
| --- | --- | --- |
| 主操作、次操作、行操作 | [Button](https://v4.primevue.org/button/) | 沿用项目按钮高度、图标、操作层级与状态语义 |
| 文本、数值、多行输入 | [InputText](https://v4.primevue.org/inputtext/)、[InputNumber](https://v4.primevue.org/inputnumber/)、[Textarea](https://v4.primevue.org/textarea/) | 标签明确，区分只读、禁用与错误；保留输入 |
| 单选下拉 | [Select](https://v4.primevue.org/select/) | 支持搜索、点选、键盘操作与当前选中状态 |
| 多选下拉 | [MultiSelect](https://v4.primevue.org/multiselect/) | 已选项可查看和移除，搜索后保留选择；占用限制属于业务扩展 |
| 输入建议 | [AutoComplete](https://v4.primevue.org/autocomplete/) | 明确必须选择已有对象还是允许自由输入，依据业务规则决定 |
| 树形对象选择 | [TreeSelect](https://v4.primevue.org/treeselect/) | 按实际层级组织；是否联动选择父子节点由业务规则决定 |
| 勾选、互斥选项、开关 | [Checkbox](https://v4.primevue.org/checkbox/)、[RadioButton](https://v4.primevue.org/radiobutton/)、[ToggleSwitch](https://v4.primevue.org/toggleswitch/) | 控件语义与业务状态一致，明确更改立即生效还是保存后生效 |
| 日期或日期范围 | [DatePicker](https://v4.primevue.org/datepicker/) | 明确格式、范围限制、清除行为；涉及时间时保留功能定义的时区语义 |
| 数据列表和分页 | [DataTable](https://v4.primevue.org/datatable/)、[Paginator](https://v4.primevue.org/paginator/) | 保留紧凑表格；排序、筛选、分页和选择按需求启用 |
| 模态表单、确认操作 | [Dialog](https://v4.primevue.org/dialog/)、[ConfirmDialog](https://v4.primevue.org/confirmdialog/) | 明确标题、主次操作、焦点与关闭行为；确认框用于需要确认的操作 |
| 侧边详情或编辑 | [Drawer](https://v4.primevue.org/drawer/) | 遵循项目已确认的抽屉关闭与未保存修改保护约定 |
| 轻量浮层、辅助提示 | [Popover](https://v4.primevue.org/popover/)、[Tooltip](https://v4.primevue.org/tooltip/) | 适配桌面视口边缘；必需信息不能只依赖悬停提示 |
| 标签页 | [Tabs](https://v4.primevue.org/tabs/) | 清晰展示当前页签，保持已定义的切换与状态保留行为 |
| 状态、反馈与加载 | [Tag](https://v4.primevue.org/tag/)、[Message](https://v4.primevue.org/message/)、[Toast](https://v4.primevue.org/toast/)、[Skeleton](https://v4.primevue.org/skeleton/) | 状态文字与颜色一致；字段错误就地显示，不能仅用短暂通知替代 |

例如：带占用信息的商户选择器可采用 Select 的交互模式与自定义选项展示；占用判断、禁选和已选项取消是项目业务规则，不宣称组件库自动提供。

## 项目视觉基线

- 表头高度、表头字号、按钮高度、图标体系和参考页面统一以 [AGENTS.md 的 UI design](../../AGENTS.md#ui-design) 为准。紧凑规格是项目定制，不标为 PrimeVue 默认值。
- 共享侧栏、顶栏、字体、语义色、边框、圆角与间距优先复用目标页面所属的共享样式。已有多个主题时，沿用该页面所属主题，不从无关页面拼接另一套视觉风格。
- 新增可复用样式时，优先扩展合适的共享 CSS 变量或类；按颜色用途、控件用途命名，避免在多页复制相同硬编码值。局部业务布局留在功能样式中。
- 颜色、字号、间距等尚未统一的数值，先查同类页面的已确认实现；本规范不凭空追加一套与现有页面冲突的数值体系。全局风格调整应有明确任务范围。
- 静态 CSS 变量可参考 PrimeVue 的基础、语义、组件三级设计变量思路，但无需使用其代码命名或主题工具。保持清楚的用途对应关系即可。

## 组件扩展规则

按以下顺序判断，而不是为了“标准化”牺牲业务表达：

1. **标准模式可满足：**采用对应结构与交互，并适配项目视觉规格。
2. **组合可满足：**组合已有控件。例如搜索输入、勾选列表与已选标签组成终端选择器，统一维护其选择状态。
3. **仍有缺口：**设计业务组件。例如营业时间编辑器、终端在线历史矩阵可保留专用布局，内部按钮、提示、选择器仍使用统一模式。

自定义或组合组件应在相关功能文档中，或小改动的交付说明中，简短记录：用途、参考组件、标准模式的具体缺口、扩展交互及复用位置。不存在标准组件映射时如实写明，不强行套用名称。

常规组合和合理扩展属于正常设计工作，无需额外逐项审批。只有改变业务规则、全局设计基线或超出用户范围时，才提出具体差异请用户决定。存在合适的共享实现时优先复用；反复出现的业务组件应沉淀到现有共享模块，保持静态架构。

## 交互与桌面验收

针对本次涉及的控件逐项核对；不相关的状态无需增加演示入口：

- **状态：**适用的默认、悬停、键盘焦点、选中、禁用、只读、加载、空数据与错误状态清楚且一致；状态信息不能只靠颜色表达。
- **表单：**标签与控件关联，必填和格式限制清楚；校验失败保留输入，按根规范定位并聚焦错误；加载期间避免重复提交。
- **选择器：**点选与搜索可用，方向键、Enter、Esc 及焦点移动符合所选模式；搜索不丢选择。占用限制和已选项移除遵循根规范。
- **浮层：**检查真实桌面视口及滚动容器，选项不被弹窗或底部操作栏裁切；打开和关闭后的焦点位置合理，模态弹窗的焦点留在弹窗内。
- **抽屉：**遵循 [Portal 右侧抽屉关闭交互](drawer-dismissal-2026-09-15.md)，包括遮罩关闭、内部交互及未保存修改保护。
- **视觉：**打开具体修改路由，核查共享页面框架、紧凑尺寸、按钮对齐、文字溢出和实际内容下的布局；页面内的设备与素材预览保持既定比例。只验收桌面浏览器。
- **交付：**区分“参考 PrimeVue 的静态实现”和研发真实组件；不以构建成功代替页面验收。纯规范文档修改检查规则一致性、链接和变更范围即可。
