# Paywizard 关联交易首版方案

日期：2026-09-15。状态：产品范围已确认，静态原型已实现并完成桌面验收；生产接口尚未接入。

## 改造结果

用户在 Transactions 找到任意一笔交易后，可以点击该行 Actions 下拉菜单中的 Related Transactions，在居中弹窗查看完整关联过程，也可以在该笔详情中查看同一份关联表。从退款、撤销或预授权完成进入时，原始交易、同级操作及后续操作均可见，每笔保留自己的金额和处理结果。

## 已确认的范围

| 决定 | 首版要求 |
| --- | --- |
| 关联边界 | 按明确的支付交易关系连接，不引入零售餐饮订单概念 |
| 主列表 | 保留逐笔流水及 Completed／Failed 两个 Tab |
| 支持类型 | 覆盖现有支持类型中有明确关联的退款、撤销、预授权增加／完成、小费调整等记录 |
| 结果展示 | 关联区包含有记录且有可信引用的成功、失败及处理中操作 |
| 查看入口 | 每笔交易的 Actions 下拉菜单新增 Related Transactions，保留 Terminal Details；交易详情内也保留关联表 |
| 列表查看形式 | 点击 Related Transactions 后打开居中弹窗 |
| 关联范围 | 从任意成员进入，展示用户权限范围内的完整支付过程 |
| 金额 | 仅展示各笔金额、币种和结果，不新增整组金额汇总 |

以下规则已落实到交易列表与详情静态原型；生产数据与权限要求仍需后端实施。

## Actions 菜单与关联查看

### 入口

在每笔交易现有 Actions 下拉菜单中保留 Terminal Details，并新增 Related Transactions 菜单项。列表不新增独立 Related 列或关联数量入口，也不采用右侧抽屉。

点击 Related Transactions 查看该笔的完整关联记录。菜单项复用同类操作的图标、尺寸和交互，不改变现有 Terminal Details、Transaction Details 等操作的目标。交易详情内继续提供关联表。

关联数据按点击的交易加载；菜单项不依赖预先取得关联数量。无关联时弹窗仅显示提示，不展示自身记录、数量或原始交易标题；详情隐藏整个关联模块。加载失败提供 Retry。首版不要求为列表每一行额外预取关联计数。

### 居中弹窗

已确认：点击 Actions → Related Transactions，关闭下拉菜单并打开标题为 Related Transactions 的居中弹窗，展示所选交易的完整关联表。弹窗复用项目现有模态样式、关闭入口与键盘行为，关联内容在弹窗内滚动；关闭后继续查看原列表。

### 关联内容

关联查看区显示关联总笔数和关联表；表内包含当前笔，并用行底色和 Current 文字标记。默认按处理时间从早到晚排序，列头明确时区，打开时定位当前笔。总笔数由后台在当前用户权限范围内返回，不按当前列表分页计算。

| 字段 | 展示规则 |
| --- | --- |
| Time | 各笔处理时间，统一显示时区 |
| Type | 保留业务类型，如 Refund；Failed 不替代交易类型 |
| Amount | 各笔金额与币种，不相加，不推算新金额 |
| Result | 各笔真实处理结果，颜色与文字同时表达 |
| Applies To | 该笔操作直接针对的交易，可访问时提供链接 |
| Transaction ID | 可定位到该笔详情的交易标识；与详情标题的 ID 标签保持一致 |

长 ID 可换行并复制；关联表在其查看区域内滚动。首版采用紧凑表格，不叠加时间线或关系树，不在关联表新增退款、撤销等执行按钮。

导航建议：点击关联交易 ID 或 Applies To 链接，关闭弹窗并在当前标签页进入目标交易详情，定位关联区并标记目标笔。直接关闭弹窗时恢复该行 Actions 按钮焦点，原列表的 Tab、筛选、分页和滚动位置保留。

## 交易详情

沿用现有侧栏、顶栏、标题、小票入口和当前笔摘要。在摘要下方、技术字段上方加入 Related Transactions 表，与 Actions 入口使用相同记录、排序、字段和结果表达。

点击表内另一笔交易 ID，更新详情地址、顶部金额与结果、技术字段、小票对象和 Current 标记；关联表保持在视野内。直接打开或刷新详情地址时，按该地址对应交易重新加载，不能回落到固定演示交易。

无其他关联记录时，详情隐藏关联模块，弹窗仅显示 `No related transactions found.`，两处均不展示仅含自身的表格；已知存在引用但原交易不可用时，显示允许披露的引用及不可用状态，不把数据缺口描述成“没有关联”。小票始终对应当前笔，该笔没有可用小票时沿用不可用状态。

## 两个 Tab 与完整关联的关系

假设消费 S 成功、退款 R1 失败、退款 R2 成功：

| 当前区域 | 内容 |
| --- | --- |
| Completed 列表 | S、R2 |
| Failed 列表 | R1 |
| S 的 Actions 关联查看或详情关联表 | S、R1、R2，S 标记 Current |
| R1 的 Actions 关联查看或详情关联表 | S、R1、R2，R1 标记 Current |
| R2 的 Actions 关联查看或详情关联表 | S、R1、R2，R2 标记 Current |

关联查询不继承列表的 Tab、日期、类型或金额过滤，但继承权限范围。列表数量、分页和现有导出只计算原筛选命中的流水。平台交易记录只保存 Completed 或 Failed 最终结果，因此关联区不出现 Pending。

返回路径建议：从弹窗进入详情后返回列表，恢复原 Tab、筛选、分页及滚动位置，不自动再次打开弹窗；用户可通过原行 Actions 再次查看。通过其他入口直接进入详情时，返回 Transactions 使用正常列表入口，不制造不存在的历史筛选。

## 直接关系与完整过程

对 `预授权 A → 完成 C → 退款 R`，从 R 进入可见 A、C、R；R 的 Applies To 为实际退款对象 C，完整过程的 Original Transaction 为 A。

对 `消费 S → 退款 R1、退款 R2`，两笔退款都直接作用于 S，彼此是同一过程的成员。后续撤销若针对 R1，Applies To 指向 R1。表格时间上的上一行不用于推断直接关系。

仅使用可信支付引用连接记录；相同卡号、金额、RRN 或外部订单号不构成自动合组依据。原始记录还未收到时，允许展示已知的关联部分；后续取得可靠记录后补齐。发生循环、冲突或无法验证的引用时保留可读记录并标明关系不完整，不无限递归或猜测关联。

## 加载与历史数据

| 状态 | 用户看到的内容 |
| --- | --- |
| 加载中 | 加载提示，保留当前笔，不先显示 0 笔 |
| 成功且无关联 | 详情隐藏关联模块；弹窗只显示无关联提示，不展示自身记录及计数 |
| 加载失败 | 在当前关联查看区显示原因和 Retry，保留当前笔与已有内容 |
| 原始记录缺失 | 已知且允许展示的引用、不可用状态及已取得的其他记录 |
| 已知历史覆盖不完整 | 提示目前展示范围，不声称完整；不估算缺失记录数量 |
| 权限受限 | 仅返回允许访问的记录及计数，不通过提示泄露隐藏记录的存在和数量 |

数据量大时分页加载，展示当前已加载数量及准确的可见总数，提供当前笔定位。关联总数不可从当前页条数推算；未知完整性不能当成已完整。

历史数据按现存可信引用查询和回溯；本方案不预先承诺某个历史覆盖日期。具体可追溯范围属于实施前数据核查项，原型应包含缺失原单和延迟补传场景。

## 实现路径

1. 原型统一列表与详情的数据来源，让详情通过交易标识加载正确记录；复用一套关联查询与表格供 Actions 关联查看、详情使用。
2. 产品复用现有交易详情和金额格式化能力，新增或独立扩展只读关联查询。已有成功子单查询参与后续交易操作时保留其原语义，避免全状态数据进入旧的额度计算。
3. 关联查询以任意流水标识进入，返回各笔详情定位 ID、实际关系、结果、金额／币种、处理时间、权限内总数和完整性；Actions 入口按需加载。
4. 核查交易流水 ID、内部关联对象 ID、外部引用之间的映射，覆盖成功、失败、处理中、跨终端、多层及迟到记录。当前源码不能证明这些数据都已完整保存。
5. 原型及产品分别验收。原型使用演示数据；产品发布前必须完成真实接口、权限和数据覆盖核验。

当前源码证据及竞品核查见[改造研究](related-transactions-2026-09-15.md)。本次已修改交易列表与详情页面。原型使用共享演示数据，未接入生产接口。实现与验证见[原型验收记录](related-transactions-implementation.md)。

## 桌面验收清单

- 每笔交易的 Actions 下拉菜单包含 Related Transactions，Terminal Details 保持可用；不新增独立关联列或右侧抽屉。
- 点击 Related Transactions 打开居中弹窗，下拉菜单关闭；关闭弹窗恢复原列表与 Actions 按钮焦点。
- 两个 Tab 均可通过 Actions 查看全部可见关联结果，离开查看后原列表位置恢复。
- 同一笔从 Actions 与详情查看时，成员、金额、结果和计数一致。
- 从退款或预授权链末端进入，能看到原始、同级及后续记录；Applies To 准确。
- 关联 ID 跳转、刷新、小票与 Current 始终对应当前交易。
- 错误和 Retry 在实际滚动区域内可见；长 ID、分页与当前笔定位可用。
- 缺失原单、迟到记录、权限限制和无关联分别表达，不伪造完整性或数量。
- 页面不出现新增的整组金额汇总；各笔币种及金额语义保留。
- 原有交易操作、列表计数和导出范围保持原规则；按项目要求不做手机浏览器验收。
