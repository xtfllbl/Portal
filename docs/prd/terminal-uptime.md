## 1. 目标与本期范围

商户、代理、服务商与 Paywizard 运维需要在未启用 Customer Alerts 时，仍能查看无人值守支付终端每天的 Payment Service 在线情况。按营业时间衡量在线表现，区分计划非营业时段、服务可联系状态与平台采集可用性，不从缺少通信推断网络或设备故障原因。

本期交付单终端首页七天摘要、七天矩阵、单日时间轴、独立 Operating Hours 配置、门店继承与终端覆盖、历史版本及可交互演示。只统计 Payment Service（OPC 服务连接），不增加 Device Connection 指标，不将连接在线解释为出货成功或交易必定成功。

现有 Customer Alerts 与 SLA Alerts 的 Monitoring Hours、触发、恢复、通知均维持当前行为。后续跟随营业时间、跨窗口离线累计及旧规则迁移不属于本期。未增加导出、跨门店批量覆盖或可复用时间表库。

## 2. 界面与导航

- 共享导航：Device Management → Uptime Matrix。面向支持无人值守业务的 Provider、Merchant、Store 视角；Billing-only 和纯 Attended 视角无此入口及直接访问能力。
- 无参数进入无人值守终端页时默认 Basic Information，直接嵌入 Service Uptime 七天摘要，位于地图及硬件/终端信息之后、Terminal Transaction Statistics 正上方；保留显式 APP / DEX 等 tab 深链。
- 摘要日格显示日期、百分比、日内状态条及当天进度。点击日格就地打开详情抽屉，Previous day / Next day 查看相邻可见日期；View history 携带 S/N 进入矩阵，可进一步选择历史日期。摘要与矩阵共用计算、权限和详情组件。
- 摘要头部只保留 Service Uptime 标题和 View history，移除装饰图标、Simulated data 标记及独立 Refresh 按钮。仍显示终端地区时区和数据更新时间；打开页面加载一次，详细矩阵保留手动 Refresh。
- 保留原有地图、硬件信息、终端详情和图片。矩阵内 S/N 使用与 Terminal List 相同的蓝色加粗链接样式（#006fd6、无常驻下划线），点击返回对应单终端页，并保留查看范围和只读上下文。
- 原型首页有独立 Uptime Matrix 分组和页面目录条目。
- 复用 Portal 侧栏、顶栏、字体、颜色、间距；没有额外副标题或新增角色演示切换器。
- 桌面 S/N 与 Store 列各 200px（中等宽度 180px / 150px），七天日期列分配剩余宽度；长店名最多两行并提供完整提示。行高约 60px、日格 48px，仅当天日格增加进度行。
- 表头采用 Terminal List 的 34px 浅灰表头、11px 字体。表单操作按钮 40px，分页行操作 36px，同一操作区等高。
- 桌面为 S/N、Store、日期列；手机将每台终端的 S/N 与 Store 放在色块行上方，默认七天可同时阅读。更长自定义范围在矩阵容器内横向滚动，不撑宽页面。单终端摘要在手机上沿用双列分行，确保百分比与当天文字可读。

## 3. 日期与历史

1. 默认最近七个当地日历日期，包含今天。单终端摘要和带 S/N 的矩阵以该终端当前（解绑时最后授权归属）的有效时区确定同一结束日。跨时区总览使用可见范围内最新当地日期作为范围结束日；每台终端的实际归日仍使用其当时有效时间表的地区时区，尚未来到的本地日期不生成状态格。
2. 历史保留三个日历月，以当地日期向前推三个月；目标月份没有对应日期时取月末。原型只允许查看保留范围内日期，单次最多 90 天。
3. 终端从权威接入当天开始展示，之前日期不展示，不填绿、不填红、不显示“未纳入统计”占位格。在多终端共用日期列时，此终端接入前的交叉位置为空且不可点击；单终端入口的日期范围直接收敛到接入当天。
4. 接入当天只统计实际接入时刻之后的有效营业时间。后续缺失观测才属于 Unknown。
5. 按时间表时区的自然日 00:00 至次日 00:00 归日。跨夜营业分别计入实际落入的日期；夏令时按实际经过时长统计，不固定以 24 小时为分母。
6. 当天只统计到本次查看的截止时刻；未来时段不纳入分母、不显示为 Unknown。没有任何已发生营业时间而仍有未来营业安排时日格和详情主指标显示 `—`，详情小字显示 `Starts at HH:mm`（终端当地营业起点）。

## 4. 在线率和状态格

令计入范围为：所选当地日期 ∩ 已接入时段 ∩ 有权查看的 Store 归属时段 ∩ 当时有效的 Operating Hours ∩ 本次截止时刻之前。

产品仅区分 Online 和 Offline 两种服务状态。Offline 表示应收到服务通信但未收到，不判断是网络中断、设备故障还是其他原因。旧原型中的 offline 与普通 unknown 缺口统一归为 Offline，不再作为 Confirmed offline 和 No report 两种产品状态。观测区间采用左闭右开 `[from, to)`；不以告警事件数量、告警阈值、成功交易或查看者本地时间推算在线时长。

计入时长大于零，且不存在营业内已知采集不可用或观测冲突时：

`Daily uptime = Online / (Online + Offline) × 100%`

历史和今天已经发生的 Offline 时长均只计入分母一次，不改动此前百分比、营业内口径与颜色阈值。全部应上报时段都未收到通信的历史营业日为 0%。非营业及未来时段不参与分母。本期不增加无真实数据支撑的丢包率、信号质量或故障原因判断。

若计入时段存在明确的平台采集故障或冲突观测，日格显示中性的 `—`，详情小字说明 `No data`，不计算单一日在线率，也不标绿；Online、Offline 与无法评估的时长在详情保留。此例外是平台数据可用性问题，不是另一种终端故障类型。营业外的采集问题不影响营业内在线率。页面查询失败保留上次成功结果并显示错误，不把一次查询失败补成终端 Offline。

| 情况 | 日格 | 百分比与详情 |
| --- | --- | --- |
| 在线率 ≥95% | 绿色 | 实际在线率，保留短暂 Offline 明细 |
| 在线率 ≥90% 且 <95% | 黄色 | 同上；90% 为黄色，95% 为绿色 |
| 在线率 <90% | 红色 | 同上；不会因离线不足告警阈值而忽略 |
| 终端当地今天，已有计入营业时长 | 健康颜色 + 时钟与 In progress | 截至本次查看的暂计百分比；提示 Today is still in progress |
| 营业内有已知采集故障或冲突观测 | 灰色 `—` | 不显示微型时间条；提示及详情小字为 No data；已有计入营业时长的今天仍附 In progress |
| 全天无营业安排 | 灰色 Closed | 不展示百分比；原始状态仍可查看 |
| 当天尚未开始营业 | 灰色 `—` | 不显示微型时间条；提示及详情小字为 Starts at HH:mm |
| 接入前、未来日期、无权查看的归属日期 | 不生成状态格 | 不可下钻 |

阈值使用未舍入值判断，为本产品经用户确认的运营分级，不是跨行业标准或 SLA 承诺。普通百分比向下保留一位小数（整数省略小数），避免 94.999% 显示为绿色边界的 95%。非满分且高于 99.95% 显示 `<100%`，实际 100% 才显示 `100%`。短暂离线不因颜色达到绿色而从时间轴消失。

In progress 表示终端当地日历日尚未结束，与是否缺报无关；营业已结束但当地日期尚未结束仍可显示。到当地次日，在下次进入页面或手动刷新时移除标签，历史不出现 Incomplete。已完成日期仍允许后续权威数据纠正。手机矩阵用时钟图标配合 Today in progress 图例节省空间，按钮无障碍名称和详情保留完整说明；首页摘要保留 In progress 文字。

日格不再整块叠加斜纹。微型时间条和详情时间轴表达 Online（绿）、Offline（统一红色）、采集不可用、非营业和未来时段；移除原 No report 的单独斜纹分类。相邻且属于同一营业计划、归属及授权边界的同类服务状态合并展示，原始证据保留在适配数据中。

默认排序依次为：有 Offline、只有采集质量问题、正常或休息；第一组按所选期间营业内 Offline 累计时长降序，使用 S/N 稳定打破并列。组织筛选与只读状态不会使无权查看的历史进入排序。

**不设置自动刷新或轮询。** 页面只在首次打开、用户操作或手动 Refresh 时更新展示。数据更新时间明确标记，未覆盖的观测区间不能无限沿用最后的 Online。

## 6. 单日详情

- 显示终端名称、S/N、发生时 Store、有效地区时区、当天营业安排、日在线率、Closed 或 `—`；无结果时以小字 No data / Starts at HH:mm 说明，以及适用时的 In progress。
- 存在已知营业内时长时，显示 Online 和 Offline 两项统计；完全没有可统计时长时隐藏两张 0m 卡，部分采集缺失仍保留已知时长及未评估时长。不得重复累加旧原型的缺报部分。Offline 的说明为未收到服务通信、原因未知；已知采集不可用或冲突仍单列无法评估时长及说明。
- 全天时间轴保留非营业和未来区间；初次接入日从实际接入时刻开始，授权中途变化时只展示有权查看的片段。
- 明细列：时间段、Payment Service 状态、是否在营业时间内、持续时长。保留秒级精度和真实服务状态变化边界，不以分钟采样吞掉短暂 Offline；相邻旧 offline 与普通 unknown 段可以合并显示为同一段 Offline。
- Previous day / Next day 只在相邻日可见时启用，禁止跨过接入、归属、保留范围或未来日期边界。
- 摘要与矩阵抽屉均使用约 240ms 右侧滑入、180ms 滑出及同步遮罩渐变；关闭按钮和 Esc 行为一致，切换日期不重复入场。遵循系统减少动态效果偏好。进入 Operating Hours 前完成抽屉退出。
- 无结果的 `—` 日格仍可点击，保留原因、时区、营业安排及原始分段；接入前、未来日期和无权查看日期继续为空且不可点击。
- 矩阵抽屉提供 Operating Hours；首页摘要抽屉提供带日期的 View history。Operating Hours 仅在当前用户可管理该终端且终端仍有授权内当前归属时启用。历史属于旧店不等于有权修改已转到其他店的终端。

## 7. Operating Hours 模型

### 7.1 归属、默认与覆盖

- Store 拥有默认时间表；Terminal 默认跟随 Store。
- 未设置时间表时按 24 小时营业处理，界面展示当前安排及地区时区。
- Terminal Custom hours 是完整覆盖，包括周计划、指定日期例外和时区，不与门店逐字段合并。
- Follow Store 会恢复门店当前有效配置；本次修改前的终端版本保留，用于解释旧历史。
- 门店保存只影响保存时正在跟随该门店的终端，不覆盖独立终端时间表。保存区展示受影响数量。

### 7.2 每周时段与日期例外

- 星期一至星期日独立选择 24 hours、Closed、Custom。
- Custom 至少一个时段，允许多个时段；结束早于开始为次日，显示 next day。
- 起止相同不允许保存；全天应选择 24 hours。时刻精度为分钟，`00:00` 可作为跨夜结束时间。
- 时段不得重叠或重复；验证包含相邻日和 Sunday → Monday 的跨夜衔接，并指出冲突的星期或日期。首尾相接不视为重叠。
- 每个指定日期最多一条例外；例外可以全天、休息或多个自定义时段。
- **指定日期例外覆盖该当地日期的常规营业安排，包括前一天跨夜延续。** 例如周五 22:00–周六 02:00，但该周六指定休息，则周六 00:00–02:00 不营业。
- 普通周计划中的 Closed 表示该星期不新开一个时段；前一天合法跨夜可延续。要明确取消某一日期的跨夜延续，使用该日期例外。编辑器预览展示最终合并后的每日安排。
- 地区时区使用 IANA 标识，随保存版本保留；地区的夏令时规则参与实际时长计算。不能根据查看者浏览器时区重写已保存安排。

### 7.3 编辑操作

| 操作 | 前置条件 | 结果 | 校验/失败 |
| --- | --- | --- | --- |
| 选择 Store or terminal | 目标在当前授权范围内 | 搜索或点选后回填目标当前时间表、继承模式及历史；切换不提交当前草稿，返回目标时重新读取生效配置 | 无匹配时保留已选目标；需要保留修改时先 Save |
| Follow Store / Custom hours | 当前目标为可管理 Terminal | 本地草稿切换；从继承切到自定义时复制当前有效安排供编辑 | Save 前不改变已生效配置 |
| 时间区搜索 | 可编辑独立时间表 | 选中地区时区后更新草稿及预览 | 未提交的搜索文本不会改变保存值 |
| 24 hours / Closed / Custom | 可编辑独立时间表 | 修改所选星期或例外；Custom 初次提供时段输入 | 不保存到永久状态 |
| Add period / Remove period | Custom 模式 | 新增或移除当前日的时段 | 空 Custom、重叠、无效时间在实际滚动区显示错误 |
| Add date / Remove exception | 可编辑独立时间表 | 新增指定日期例外或移除草稿条目 | 重复日期、无效日期、跨夜冲突阻止保存 |
| Save | 管理权限仍有效、配置有效 | 生成从保存时刻生效的新版本，记录修改人及操作；关闭编辑器并更新矩阵 | 权限不足、版本冲突或存储失败时保留输入、定位并聚焦错误；不伪造成功 |
| Cancel / 关闭 / Escape | 编辑器已打开 | 丢弃本次未保存修改并返回矩阵 | 不新增版本、不写审计 |
| Change history | 有权查看目标 | 查看版本生效时间、修改人、继承模式、时区 | 不提供回写历史版本的按钮 |

搜索下拉同时支持键盘上下键、Enter、Escape、Home、End；候选独立滚动，使用顶层浮层避免被弹窗内容和底部按钮裁切。错误消息滚动进入可视区，保存/取消按钮保持等高。

## 8. 历史版本、换店与权限

1. 每台物理支付终端按 S/N 保留历史，同一 TCI 替换新 S/N 后不能把新旧设备合为一行。
2. 每个 Store 归属区间都有生效开始与结束。某日中途换店时，各门店只统计有权查看的对应时间片。
3. 历史权限为“记录发生时的 Store”与“查看者当前有权访问的 Store”交集。原店保留移出前的历史，新店不获得移入前历史；授权上级可查看双方范围。
4. 解绑不立即删除过去的历史，保留至三个月期限；未归属区间不计入任何门店的营业在线率。
5. 换到不同 Store 后默认跟随新店时间表，旧的独立覆盖只参与旧历史解释，不自动带入。
6. 时间表保存不重算生效前的历史；当日中途保存，生效前后使用不同版本。
7. 允许权威观测补齐或纠错，用当时生效的时间表重新计算；这与用户通过编辑营业时间重写历史不同。
8. 查看与管理权限分开。管理 Store 时间表需要 Store 管理权限，管理终端覆盖需要该终端的当前管理权限；单靠能够看见历史不能获得当前编辑权限。

| `scripts/terminal-uptime-summary.js` | 无人值守终端首页七天摘要、就地抽屉及历史链接 |

| `scripts/customer-account-data.js`、`scripts/customer-account-directory.js` | 复用的演示组织/门店/终端目录 |

所有当前数据仍是模拟；详细矩阵保留 Simulated data 标记，首页摘要按用户要求移除该标记。样例覆盖正常、不同原始来源的 Offline、平台采集异常、分段营业、跨夜、日期休息、新接入、换店和解绑场景。本地存储键为 `paywizard.terminal-uptime.demo.v1`，保存配置和版本，刷新页面不重置。进入页面时推进本次模拟观测截止时间，同时保留时间表、归属、审计与预设异常；修复跨日重开仍使用旧观测而产生大面积缺报的问题。此动作仅发生一次，不设置轮询。模拟观测不会发送邮件、产生真实告警或连接真实 Payment Service。旧适配器的 offline、unknown、confirmedOffline、unreported 仅是内部原始记录与核对字段，不代表已证实的故障原因或两个用户状态；`offline` 汇总本身已包含普通缺报一次，统一展示直接复用该合计。

现有 Portal Access Profile 和 `scope` / `access=view` 是演示与验收上下文，不是生产身份验证或安全授权。原型的前端筛选不能保护真实多租户数据；生产必须在服务端裁剪返回数据。

### 9.2 生产所需数据契约（目标，尚未接入）

| 数据 | 必需内容与口径 |
| --- | --- |
| 身份与权限 | 可信登录主体、当前可见 Store 范围、Store/Terminal 管理权限；组织树权威 ID |
| 终端身份 | 稳定物理 S/N、展示名称、真实接入统计时间；不能从固定样例或第一条告警猜测 |
| 归属历史 | `{ sn, storeId, from, to }`，准确覆盖加入、换店、解绑；同一时刻归属不得冲突 |
| Payment Service 观测 | UTC 实际事件时间或有界区间 `{ from, to, state, cause? }`；适配上游原始状态，对产品统一输出 Online / Offline；已知平台采集异常单独标记。缺少通信不能成为某种已证实故障原因 |
| 数据质量 | 权威的新鲜度、缺失、冲突、迟到和修正口径；明确 cause 区分 unreported、collection_failure、conflicting_observations。没有故障证据时不臆测原因；不能把页面查询失败当作终端离线，也不能无限延长最后一条 online |
| Operating Hours | 地区时区、七天计划、日期例外；终端 mode 为 follow/custom，custom 覆盖全部内容 |
| 版本与审计 | 服务端生效时间、可信修改人、版本号、所属资源；过去版本不可被当前配置替换 |
| 返回元信息 | 观测更新时间、查询截止时刻、保留边界、每行实际可见起点；请求应支持分页与筛选 |

建议接口职责如下，路径可按后端规范调整：

- 查询矩阵：传入日期、组织/Store/S/N 筛选、状态过滤和分页；服务端按当前身份返回授权内汇总。
- 查询单日：返回同一汇总口径下的原始分段、有效营业区间和版本来源；禁止返回另一门店的时间片。
- 查询/保存 Store Operating Hours；查询/保存 Terminal mode 与覆盖计划；保存携带期望版本号。
- 查询历史版本与审计；观测补齐通过下一次手动刷新呈现。
- 保存校验错误返回字段位置与说明；并发冲突返回版本冲突且不丢草稿；权限失效应清除无权查看内容。暂时读取失败可保留带更新时间的上一次授权快照。

生产监控采集频率、判离线阈值、数据新鲜度阈值与观测修正流程需要 Payment Service 后端团队提供真实契约。本期不编造这些服务已实现，也不以浏览器轮询代替采集。三个日历月之外的原始历史清理和服务端审计保留策略需分别实现，原型查询边界不等于生产清理任务已上线。
