# 服务商季度账单产品需求文档

版本：V1.0  
基准日期：2026-10-28  
状态：产品与研发评审稿  
适用范围：Maintain 服务商账单管理、服务商 Portal Billing & Payments、账单付款页

本文汇总 2026 年 10 月 28 日的服务商账单业务决定、当天后续调整及当前正式原型。正文描述产品交付要求；原型演示能力、尚需研发落实的部分及资料差异见第 13 节。金额示例用于解释规则，各服务商最终收费以其已配置标准和运维发布账单为准。

## 1. 背景与目标

平台需要向服务商收取其服务范围内设备的激活费和月服务费。设备可能启用、解绑、重新启用或转移，当前在线台数或当前归属不足以还原历史应收，因此需要根据实际服务事件计算费用，再由运维核对并形成季度账单。

本期目标：

1. 按服务商汇总直属及各级下属代理商、商户、门店的设备费用，明确费用承担方。
2. 清楚解释每笔激活费及每个月服务费的依据，保留历史费用和价格。
3. 支持运维核对、调整和发布账单；服务商查看最终应收并主动支付。
4. 防止重复计费、重复付款、修改账单后按旧金额付款，以及内部调整记录对外泄露。

## 2. 范围与角色

### 2.1 本期范围

| 范围 | 要求 |
| --- | --- |
| 收费设置 | 按服务商配置币种、计费启用月份、激活费、月服务费及未来生效价格 |
| 费用计算 | 根据设备服务事件产生费用，支持历史激活费补收及逐月服务费累计 |
| 季度账单 | 生成草稿、运维核对调整、发布、未付修订、零金额保留 |
| 服务商自助 | 查看本服务商已发布账单、费用明细、支付记录及未付账单数量 |
| 付款 | 从账单进入现有付款页，一次性支付该张季度账单；支持链接有效期管理 |
| 核对依据 | 在账单内查看系统试算、来源事件和操作记录，不再设置独立 Service Fee Log 入口 |

本期不扩展固定期数分期合同、自动扣款、部分付款、退款、贷项账单、税费计算、自动停机、自动催收或新增邮件通知。原有商户账单及独立收款的规则和流程保持独立；如后续需要上述能力，应另行定义。

### 2.2 角色与权限

| 角色 | 可见内容 | 可执行操作 |
| --- | --- | --- |
| 平台运维 | 所有服务商账单、费用设置、原始试算、来源事件、内部调整记录 | 配置费用、生成草稿、修改未付账单、发布、管理支付链接有效期 |
| 普通服务商 | 本服务商已发布账单的最终收费内容、对客说明及支付记录 | 查询、查看、进入付款页主动付款 |
| 持有效链接的付款人 | 链接对应的已发布账单最终内容及付款结果 | 在允许付款时支付该张账单，无需登录 Portal |
| 下属代理商、商户、门店 | 不因纳入服务商收费范围而取得本功能账单权限 | 本期不提供服务商账单管理或付款入口 |
| WizarPOS 自有服务商 | 不开放本功能的 Billing & Payments | 直接访问列表或详情也不得取得账单；代入该实体时同样适用 |

服务商的责任范围覆盖其各级下属，不将同一费用再次拆给下属对象承担。WizarPOS 自有服务商例外不影响 Maintain 运维管理，也不将独立第三方服务商 Civitronic 视为 WizarPOS 自有实体。

权限必须落实到数据访问层。隐藏菜单、修改地址或切换前端身份均不能绕过服务商范围；账单详情、季度筛选选项和未付数量采用同一权限范围。

## 3. 核心业务概念

| 概念 | 定义 |
| --- | --- |
| 物理设备 | 以 S/N 识别的机器；同一设备可经历多段服务期间 |
| 服务期间 | 绑定后成功提交参数推送并启用服务，至解绑结束的一段服务关系 |
| 符合条件的激活 | 首次启用，或更换服务商、商户后的重新启用；产生一次激活费 |
| 费用事件 | 形成某笔激活费或某月服务费的业务事实，后续解绑不会自动删除该事实 |
| 计费启用月份 | 各服务商分别确定的月服务费起算下限；区别于设备启用月份和功能上线日期 |
| 系统试算 | 根据历史服务事件、适用费率形成的原始收费项目和金额 |
| 最终应收 | 运维核对和调整后发布给服务商的收费项目、数量及金额 |
| 季度账单 | 某一服务商在一个自然季度的应收汇总；同一服务商同一季度只保留一张账单 |

**统计台数、收费数量、费用事件数须分别理解。**例如系统记录 20 次符合条件的激活，运维决定按 18 次收费，原始 20 次激活记录仍保留。月服务费按各月符合条件的服务期间计费，不能简单使用季度末设备数乘以三个月。

## 4. 收费标准与时间口径

### 4.1 服务商费用配置

| 字段 | 规则 |
| --- | --- |
| 服务商 | 从完整服务商目录中选择；未配置费用的服务商也应可发现 |
| 计费币种 | 每个服务商固定一种币种，激活费、月服务费、账单和付款使用同一币种，不自动换汇；当前原型支持 USD、CAD、EUR |
| 计费启用月份 | 各服务商独立确定；可以不同于其他服务商，历史导入后据此确定月费起算范围 |
| 激活费 | 默认 2.00／台／次符合条件的启用，可按服务商调整 |
| 月服务费 | 默认 7.99／台／月，可按服务商调整 |
| 价格生效月份 | 初始标准从计费启用月份生效；后续调价从约定未来月份生效，不早于计费启用月份 |

2.00 和 7.99 均以该服务商的计费币种计价，不表示不同币种之间进行了换算。数量为非负整数；单价和最终金额为非负数，当前支持币种最多保留两位小数。减免通过调整正向收费项目或将应收减至零实现，本期不新增负金额账单。

所有费用事件归属、月份、季度和支付链接有效日期统一按 **UTC** 判断，界面应明确标识。自然季度为 1–3 月、4–6 月、7–9 月及 10–12 月。跨年、月末和时区边界也按这一口径处理。

### 4.2 历史价格保护

新价格只适用于生效月份及以后对应的费用，不自动改写已发生费用、原始试算或已有账单。季度内存在多个价格时，费用明细应保留各自适用价格，不能用最新价格重算整个季度。

修改未来收费标准与修改某张未付账单是两种独立操作。运维对单张账单的减免或追补不自动改变后续价格；已付账单不得通过调价被修改。

## 5. 设备计费规则

### 5.1 激活费

符合条件的服务启用，以**参数推送成功提交**为触发点，不等待设备回执；提交失败不收取该次激活费，也不据此建立已启用服务期间。设备上线、首笔交易或单纯保存配置均不代替该触发点。

| 场景 | 是否新增激活费 | 月服务费处理 |
| --- | --- | --- |
| 设备首次符合条件地启用 | 是 | 启用当月免收，次月起计费 |
| 更换商户后重新启用 | 是，即使物理设备 S/N 不变 | 新服务期间当月免收，次月起计费；旧期间已发生费用保留 |
| 更换服务商后重新启用 | 是，归属新服务商 | 新服务期间当月免收，次月起计费；原服务商已发生费用保留 |
| 同一商户内直接转店，服务持续 | 否 | 继续原服务期间，不因转店获得新的免费月 |
| 同一商户解绑后重新启用 | 否 | 建立新服务期间，重新启用当月免月费，次月起计费 |
| 普通参数更新或重复推送 | 否 | 不重建服务期间，不重新获得免费月 |
| 参数推送提交失败 | 否 | 不启动新服务期间的计费 |

激活费按符合条件的服务启用收取，**不是一台物理机器终身只收一次**。同一业务事件的重试或重复导入不得重复生成激活费。

### 5.2 月服务费与解绑

1. 启用当月为优惠月，不按天折算；次月 1 日开始形成月服务费。
2. 服务持续时，每个收费月份收取整月费用。
3. 解绑结束该段服务。若解绑当月已进入收费月份，仍收整月费用；次月起不再对已结束期间计费。
4. 若在启用当月解绑，该期间仍处于免费月，不因此补收当月月费；已触发的激活费保留。
5. 解绑后重新启用统一遵循“启用当月免月费、次月起收费”。是否再次收激活费，另按商户和服务商是否变化判断。
6. 已经产生的费用不会因后续解绑、重绑或转移自动撤销。需要减免时，由运维明确调整账单并记录原因。

### 5.3 典型场景

以下日期均为 UTC，假设计费规则已启用。

| 场景 | 应收结果 |
| --- | --- |
| 1 月 2 日或 1 月 31 日首次启用 | 两者均收一次激活费，1 月免月费，2 月 1 日起计费 |
| 3 月 5 日解绑，之前已处于收费月份 | 3 月收整月服务费，旧期间 4 月不再收费 |
| 上述设备 3 月 20 日在同商户重新启用 | 3 月旧期间费用保留，新期间不增加 3 月月费；4 月恢复收费，不再收激活费 |
| 上述设备到 4 月才在同商户重新启用 | 3 月旧费用保留；4 月新期间免月费，5 月开始收费，不再收激活费 |
| 3 月由服务商 A 解绑，3 月转到 B 并启用 | A 已触发的 3 月月费保留；B 收新激活费，3 月新期间免月费，4 月起计月费 |
| 同商户持续服务期间由门店 A 转到门店 B | 不新增激活费，原月费连续计算，保留归属变更依据 |

### 5.4 存量设备与历史补收

先拉取历史数据，再按每个服务商确认的启用月份计算。设计前提为平台具备所需历史记录，本期不增加历史数据缺失补录流程；这一前提不代表已核实生产数据完整性。

- 启用月份之前的服务费不补收。
- 历史符合条件的激活费需要补收，列入首张季度账单，单列“历史激活费”。
- 同一收费事件已有付款或未付应收记录时，不得因导入再次生成收费。
- 已确认历史金额的，保留原金额；没有旧价格记录的，采用计费启用月份确认的激活费标准。
- 机器后来转移，不自动免除原服务商尚未收取的历史激活费。
- 已持续服务的存量设备，不因平台开始计费而获得新的免费月；月费从设备次月起算规则与服务商计费启用月份中较晚的月份开始。

例如，设备 1 月启用，服务商 7 月开始计费，设备持续服务：首张 Q3 账单包含尚未收取的历史激活费，以及 7、8、9 月月费；不收 1–6 月月费。若该设备已有激活费应收记录，则不再补收。

### 5.5 季度计算示例

某服务商币种为 USD，激活费为 2.00，月费为 7.99，7 月开始计费。A、B 两台设备分别于 7 月 2 日、7 月 31 日首次启用，C 设备于 1 月启用且历史激活费尚未收取，三台均持续服务至 9 月结束。

| 收费项目 | 数量 | 单价（USD） | 金额（USD） |
| --- | ---: | ---: | ---: |
| 历史激活费：C | 1 | 2.00 | 2.00 |
| 本季度激活费：A、B | 2 | 2.00 | 4.00 |
| 7 月服务费：C | 1 | 7.99 | 7.99 |
| 8 月服务费：A、B、C | 3 | 7.99 | 23.97 |
| 9 月服务费：A、B、C | 3 | 7.99 | 23.97 |
| **系统试算合计** | | | **61.93** |

若运维将本季度激活费由 4.00 调整为 2.00，则最终应收为 59.93。系统试算仍为 61.93，原始激活记录不变，内部记录调整原因；服务商看到最终收费内容及必要的对客说明。

## 6. 账单生命周期

### 6.1 主流程

配置服务商费用 → 持续记录设备服务与费用事件 → 季度结束后生成草稿 → 运维核对、必要时调整 → 发布 → 服务商查看并付款 → 支付成功后锁定。

系统负责计算初稿，运维负责确认最终应收和发布。首次发布前，服务商不可见；发布后，只要尚未支付且没有结果未明的支付请求，运维仍可修改。

### 6.2 状态与操作

| 状态 | 含义 | 运维可操作 | 服务商／付款人可操作 |
| --- | --- | --- | --- |
| 草稿 Draft | 已生成，尚未发布 | 核对、调整、保存、发布 | 不可见、不可支付 |
| 未付 Unpaid | 已发布且应收大于零 | 调整、保存、管理链接有效期 | 查看；链接有效时付款 |
| 支付处理中 Processing | 支付已提交，结果尚未确认 | 查看，暂时禁止修改及新的支付 | 查看处理状态，禁止重复付款 |
| 已付 Paid | 已确认付款成功 | 只读查看，不得修改收费内容 | 查看最终账单和付款记录 |
| 无需支付 No payment required | 已发布且应收为零 | 查看；按未支付修订规则调整 | 查看，无付款入口 |

支付处理中是付款处理状态，结果确认前账单仍未结清。确认失败后恢复未付可修改状态，确认成功后进入已付；网络超时不直接视为失败。

支付链接过期是链接状态，**不改变账单未付事实**。界面应同时表达“未付”和“链接已过期”，不能将过期理解为取消账单、已结清或设备停用。

### 6.3 生成与发布

- 仅允许对已结束的自然季度正式生成账单，不生成未来季度或当前未结束季度。
- 生成季度不得早于该服务商计费启用月份所在季度。
- 同一服务商、同一季度已存在账单时，提示进入现有账单核对，禁止重复生成。
- 初稿分别列出历史激活费、本季度激活费、季度内各月份服务费，并保留价格差异。
- 发布前展示服务商、季度和最终金额；正金额账单同时确认链接有效日期，默认发布后 30 天。
- 发布零金额账单时保留账单，状态为“无需支付”，不提供支付链接。无账单与已核算但零应收必须可区分。
- 发布是使账单对服务商可见，不自动代表已发送邮件或已发起扣款。

### 6.4 运维调整

运维可以调整收费项目名称、收费数量、单价和最终金额，并按业务需要新增或移除项目。修改数量或单价时先联动计算金额，允许再明确修改最终金额；账单总额即时更新。

修改费用或对客备注时，必须填写内部调整原因。保存保留修改人、时间、原因、修改前后金额及对应收费内容；原始试算和来源事件保持独立。对客备注与内部原因分开，必要的收费差异通过对客备注解释，不将内部操作记录展示给服务商。

已发布未付账单保存后立即更新同一账单的有效内容，账单编号及既有支付链接不变，不新建另一张账单。金额改为零时停止提供付款；零金额账单修订为正金额后恢复未付并配置有效支付链接。已付账单不提供编辑操作。

## 7. 页面与交互需求

### 7.1 入口与导航

| 入口 | 页面用途 |
| --- | --- |
| Maintain → Billing → Billing Overview | 保留现有账单总览，并提供服务商账单访问入口 |
| Maintain → Billing → Service Provider Billing | 服务商季度账单工作区 |
| Maintain → Billing → Billing Setup | 保留原有账单创建功能，不作为设备季度账单的固定分期入口 |
| 服务商账单工作区 → Fee Settings／Set Up Fees | 查看、初始化或调整服务商费用 |
| 服务商 Portal → Billing & Payments | 当前服务商的已发布账单及付款入口 |

Maintain 的 Billing 为独立菜单分组，顺序为 Billing Overview、Service Provider Billing、Billing Setup，面包屑与当前菜单同步。已移除的 Service Fee Log 不再回加，旧地址跳转服务商账单列表；计费依据保留在账单详情的 Source events。

### 7.2 运维服务商账单工作区

按当前正式原型采用左侧服务商导航、右侧账单工作区：

- 左侧支持搜索、点选、键盘操作及 All service providers；服务商为平级收费对象，不虚构服务商之间的上下级关系。
- 目录包含已配置及未配置费用的服务商，搜索只过滤目录，不清空当前选择。
- 右侧显示当前服务商名称；进入单服务商后不重复显示表格中的服务商列。All service providers 列表保留该列。
- 已配置对象提供 Fee Settings 和 Generate Bill；未配置对象显示“费用未配置”及设置入口，不能直接生成账单。
- 页签为全部、草稿、未付、已付；零金额账单在全部账单中可见。
- 支持账单编号搜索；全部服务商视图同时支持服务商名称搜索。支持季度筛选和分页，当前原型每页 10 条。
- 列表字段为账单编号、适用的服务商列、季度、金额及币种、状态、链接有效日期、操作。
- 未付及草稿可进入 Review，已付进入只读 View。进入详情再返回时恢复服务商、搜索、季度、状态和页码；重置账单筛选不清空当前服务商。
- 从当前服务商进入费用设置或生成账单时，自动带入当前对象。

### 7.3 运维账单详情

顶部显示账单编号、服务商、UTC 账单期间、币种和状态；主区与金额汇总区并排呈现。

| 区域 | 内容 |
| --- | --- |
| Charges | 最终收费项目、数量、单价、最终金额；可编辑状态下提供条目调整、对客备注及内部原因 |
| System calculation | 原始系统数量、单价和试算金额，只读 |
| Source events | 本账单原始试算对应的事件；支持查看单条事件详情 |
| Activity | 保存、发布、调整及链接有效期修改的操作记录 |
| 金额汇总 | 激活费、服务费、系统试算、调整差额、最终总额及适用的支付链接操作 |

事件详情包含事件类型、UTC 时间、服务商、代理商、商户、门店、适用的 Terminal Name、明确标注的 S/N、原始计算费用、原因及关联账单。Terminal Name 与 S/N 分开；没有名称时不补入 S/N 或占位名称。

草稿提供 Save Draft、Publish Bill；已发布未付提供 Save Changes。已付或付款结果未明时不提供编辑提交操作。存在未保存修改时，返回、取消或关闭相关编辑界面需要保护输入。

### 7.4 服务商账单列表与详情

列表仅显示本服务商已发布账单，页签为全部、未付、已付。支持账单编号、季度筛选及分页；季度选项也仅来源于本服务商已发布账单，不泄露其他服务商或未发布草稿的季度。

详情仅显示最终费用、最终收费数量和金额、币种、必要对客说明、链接有效期及付款记录；不展示原始试算、内部调整差额、内部原因和来源事件引用。付款记录包括付款编号、时间、金额币种、方式品牌／尾号和成功状态。

未付且链接有效时提供 Pay now；过期时说明联系运维延期；已付显示付款结果，无需支付显示零应收说明。付款结果未明时明确显示处理中并防止再次提交。

### 7.5 未付账单数字提醒

Billing & Payments 菜单旁显示当前服务商**已发布、金额大于零且尚未支付**的账单张数：

- 包含链接过期和付款结果未明的账单。
- 不含草稿、已付、零金额账单及其他服务商账单。
- 支付成功后递减，数量为零时隐藏，不显示无意义的 0 标签。
- 在其他 Portal 页面也可见；同源不同标签页操作后同步更新。
- 运维服务商导航的未付数字采用同一口径。不改变已有商户 Billing Overview 的关注数量定义。

## 8. 支付与链接规则

### 8.1 主动付款

服务商从账单跳转现有付款页面，一次性支付整张季度账单。付款页展示服务商、账单编号、季度、当前费用项目及数量、应付金额、币种、有效期和对客备注；复用现有付款信息填写与校验。

该账单不建立后续自动扣款授权，也不使用原商户固定期合同的授权。支付成功后保存本次实付对应的账单内容和金额，账单变为已付并锁定。再次打开账单或链接时只显示结果，不重复收费。

### 8.2 金额变化与并发

| 场景 | 必须行为 |
| --- | --- |
| 付款页打开后，运维修改了收费内容或金额 | 提交时发现版本变化，展示最新账单并要求重新确认；不能按新金额静默扣款，也不能用旧金额结清新账单 |
| 多人同时编辑未付账单 | 拒绝过期版本覆盖，提示重新加载最新内容 |
| 支付已提交且结果未明 | 暂停账单修改及新的支付，等待原请求结果 |
| 确认支付失败 | 保持未付，解除处理中限制；允许按有效账单再次付款或由运维修改 |
| 网络超时、页面关闭或回调迟到 | 查询并核实原请求结果，不能直接标失败后再收一次 |
| 重复提交、多个付款页或重复回调 | 同一账单最多一次成功结清；不得产生重复收款记录 |
| 支付成功后收到旧失败结果 | 保持已付，不恢复可付款或可修改状态 |

上述保护必须由正式服务端与支付渠道共同保证，不能只依靠按钮禁用或浏览器存储。

### 8.3 有效期与延期

付款期限直接使用支付链接有效期，不另设独立账单到期日。默认发布后 30 天，运维可以设置或延期；当前规则按 UTC 日期判断，有效日期当天仍可支付，次日过期。

延期保留同一账单与既有链接，不重算设备费用、不改变应收金额、不创建新账单。延期后付款人通过原链接查看并支付当前账单。链接过期不自动停用设备服务，也不撤销已发生费用。

零金额账单不提供有效支付入口；已付账单不提供继续收款能力。复制支付链接失败时提供可手动复制的完整地址。

## 9. 业务数据与可追溯要求

| 对象 | 必须保留的信息 |
| --- | --- |
| 服务商收费标准 | 服务商、币种、计费启用月份、各版激活费与月费、生效月份 |
| 设备服务历史 | S/N、可选名称、事件发生时的服务商／代理商／商户／门店、启用及解绑时间、启用原因 |
| 费用事件 | 唯一业务依据、所属服务期间、费用类型、适用月份、数量、价格及金额、已入账或收取关系 |
| 账单 | 唯一编号、服务商、季度、币种、原始试算、最终收费内容、状态、版本、发布时间、对客备注 |
| 内部调整记录 | 操作者、时间、原因、修改前后收费内容及金额；与对客备注分开 |
| 支付链接 | 对应账单、有效期、可付款状态及延期记录；修订和延期保留既有链接关系 |
| 支付记录 | 原请求标识、对应账单版本及实付内容、金额币种、支付结果与时间、可展示的付款方式摘要 |

设备当前归属变化不得覆盖其历史费用责任方。原始试算、最终应收与支付时的账单内容应可核对；不以修改历史设备事实来解释运维商业调整。

## 10. 异常与体验要求

| 异常或空状态 | 处理要求 |
| --- | --- |
| 未配置服务商费用 | 明确提示并提供 Set Up Fees，不伪装为零费用账单 |
| 已配置但尚未出账 | 显示暂无账单；不等同于已核算无需支付 |
| 搜索无结果 | 说明没有匹配结果，允许修改筛选；保留当前服务商选择 |
| 重复生成或未结束季度 | 阻止操作并说明原因；重复季度引导查看已有账单 |
| 数量、金额、日期或必填项无效 | 就近指出问题，保留输入；不得静默纠正成其他收费内容 |
| 保存、发布或加载失败 | 明确反馈，允许重试；在实际滚动容器内定位并聚焦错误，不能被固定栏遮挡 |
| 服务商越权、账单不存在或链接不可用 | 不返回无权内容，提示返回本方账单或联系发送方 |
| 支付处理中、旧版本冲突或结果未知 | 明确说明当前状态及下一步，不能提示已付或直接重新收费 |

界面遵循现有 Portal 静态原型规范：共享侧栏、顶栏、字体、语义色和图标；紧凑表格使用 34px 表头、11px 字号；表单操作默认 40px，行操作默认 36px，同一操作区等高。去掉装饰性副标题，不添加比较方案切换等演示控件到正式流程。

选择器支持直接点选、搜索及键盘操作，搜索不丢失已选项，弹层独立滚动且不被弹窗或固定操作栏裁切。状态不能仅靠颜色表达；只读、禁用、加载、空状态和错误分别呈现。页面按桌面浏览器验收，本项目不要求手机浏览器兼容检查。

## 12. 本期不重新打开的产品决定

| 主题 | 当前决定 |
| --- | --- |
| 激活费是否终身一次 | 否；按符合条件的服务启用判断，更换商户或服务商后可再次收取 |
| 是否等待设备回执 | 否；以参数推送成功提交为触发点 |
| 是否按天计算首月 | 否；启用当月免月费，次月起整月收费 |
| 重新启用是否也有优惠月 | 是；解绑后重新启用使用同一规则 |
| 发布是否立即锁定金额 | 否；未支付仍可调整，支付结果未明暂锁，已付锁定 |
| 是否向服务商展示内部调整 | 否；仅最终收费内容及必要对客说明 |
| 零金额是否不出账 | 否；保留“无需支付”账单 |
| 是否另设到期日或到期停机 | 否；沿用链接有效期，不因过期停用设备 |
| 是否沿用固定期合同自动扣款 | 否；季度后付，由服务商主动付款 |
| 是否新增历史数据缺失处理流程 | 否；按具备所需历史记录设计，真实数据接入需研发核实 |

## 13. 原型边界与研发评审事项

### 13.1 当前能力和交付边界

当前为静态 HTML／CSS／JavaScript 原型，已包含收费设置、季度账单、系统试算与事件查看、运维调整发布、服务商查看、链接延期、模拟支付和菜单未付提醒。数据属于同源浏览器，标签页间可同步，跨浏览器不构成共享的权威账单。

当前付款只模拟成功，不代表真实支付渠道、失败恢复、回调处理或跨端并发已完成。历史导入、费用事件接入、持续计费、服务端身份及权限、可靠支付互斥、真实付款结果核对均需研发实现。未来价格的前端保存也不代表生产计费任务已接入。

演示数据包含 2026 Q1–Q4 四个季度。Q4 是预先构造的季度结束样本，其发布时间在 2027 年 1 月；不能据此认为 2026 年 10 月已可正式发布 Q4 账单。真实生成规则仍要求季度结束。

本次仅编写需求文档，未修改页面、发起扣款、发送账单或重新执行浏览器验收。既有设计文档中的测试记录属于相应实现批次，不作为本次 PRD 已完成生产验收的声明。

### 13.2 研发评审需明确的实现事项

| 事项 | 本文已确定的要求 | 需落实的内容 |
| --- | --- | --- |
| 服务事件来源 | 成功提交参数推送、解绑和归属变更决定计费 | 对应生产事件、业务唯一标识、事件时间及历史关系的取得方式 |
| 历史导入与去重 | 既有应收和已付款的同一事件不重收，历史已确认金额保留 | 与历史收费台账对应、导入核对及重复导入控制 |
| 季度初稿生成 | 已结束季度、唯一账单、运维核对后发布 | 生成草稿的任务触发方式及失败补偿；不自动发布 |
| 跨端修订与支付 | 旧版拒付、结果未明锁定、成功内容留存 | 服务端版本控制、支付互斥、渠道幂等及超时查询 |
| 支付失败恢复 | 确认失败后恢复未付，未知结果不能重收 | 真实拒付、回调延迟和异常中断的恢复流程 |
| 数据权限 | 服务商只读自身最终账单，内部信息不对外 | 服务端裁剪、链接访问校验及角色权限映射 |

以上是已确定规则的落地事项，不改变计费规则，也不代表已承诺新增页面或额外业务流程。

### 13.3 资料差异说明

- 早期 ADR 0019 记录“支付并发保护尚未在原型实现”；当前脚本已经具备本地版本检查、处理中限制及旧版付款拒绝。本文采用更新后的原型事实，同时保留“服务端跨端保护尚需实现”的边界。
