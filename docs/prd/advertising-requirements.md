# 无人值守终端广告管理需求文档

日期：2026-09-18  
版本：研发评审稿 v1.0  
阅读对象：产品、研发、测试、市场与销售  
页面依据：`45.advertising.html`、`1.terminalmanage_nayax.html` 的 Advertising 部分

本文将已确认的页面交互和现有广告规则整理为正式产品需求。除明确标注为“待确认”的事项外，研发应保持本文描述的业务行为；技术实现由研发设计。当前页面是浏览器本地原型，不能据此认定正式服务端、终端分发、下载或真实播放已经实现。第 10 节列出落地所需能力，第 12 节列出尚不能由原型决定的事项。

## 1. 为什么要做

无人值守设备除了完成支付，也有展示商品推广、门店活动和品牌内容的屏幕使用场景。运营人员需要在 Portal 集中管理这些内容，按门店或单台终端配置，避免逐台维护；排查某台设备时，也需要知道它目前配置了哪条广告规则、配置从哪里来。

本功能的产品目标是：让现有管理客户能够复用素材、批量配置广告、清楚识别覆盖范围，并在不干扰支付的前提下使用终端屏幕开展推广。

| 客户场景 | 需要解决的问题 | 本期提供的能力 |
| --- | --- | --- |
| 连锁门店统一开展促销 | 同一内容需要覆盖多家门店，逐台选择容易遗漏 | 按门店配置，后续符合条件的新终端自动纳入 |
| 单台设备有独立推广需求 | 某台设备所处位置或经营内容不同 | 在不与已有规则冲突的前提下，单独选择终端 |
| 运营人员核查配置 | 从设备详情无法知道当前广告及来源 | 终端详情展示当前广告、素材和门店／单台配置来源 |
| 同一规则被多家门店共用 | 修改时容易误以为只影响眼前这一台 | 统一在 Campaign 中编辑，提示共享覆盖范围 |

面向市场的产品表述可使用：**“通过 Paywizard Portal 集中管理无人值守终端的广告素材与播放配置，按门店或终端统一组织推广内容，并从终端详情追溯当前配置。”**

本期不提供曝光、播放次数、点击、转化或广告收益统计，因此不承诺广告效果归因、收入提升或投放结算能力。设备端实际播放能力必须在终端联调验收后才能作为交付能力对外承诺。

## 2. 本期范围与用户

### 2.1 交付范围

- Advertising 管理页：Campaigns 列表、创建／编辑／复制／发布／停止规则、Media Library 素材管理、目标选择与占用提示、编辑器中的终端预览。
- 无人值守终端详情：Advertising Tab，展示当前配置、预览素材、进入当前终端的 Campaigns 列表并返回。
- 正式接入所需的后端规则：数据持久化、权限校验、目标唯一占用、发布版本、门店成员变化后的覆盖更新。不能只实现页面效果。
- 终端播放的产品行为按第 7 节执行；实际支持机型、分发协议、离线策略和交付时效须按第 12 节完成评审。

仅要求桌面浏览器使用。终端详情的广告能力限于 Unattended；Attended 和 Card Reader 不因本需求新增广告能力。

### 2.2 账号与权限

沿用现有 Portal 管理账号，不新增独立广告主账号或广告审批角色。当前原型向 WizarPOS Provider、Full-Service Provider、Full-Service Merchant、Unattended Provider、Unattended Merchant、Unattended Store 开放广告入口；生产角色名称及动作权限应与正式权限系统核对。

正式产品必须同时校验页面访问、数据查看及修改权限。用户只能查询和配置其授权范围内的门店、终端、规则与素材，直接打开 URL 或调用接口也不能越权。原型展示完整演示目录，不是跨商户可见性的授权依据。素材跨账号共享方式和共享规则的编辑权限详见第 12 节。

### 2.3 本期不包含

不新增广告主入驻、审核流程、广告收费／结算、竞价或优先级投放、随机播放、日期／时段排期、播放统计、Deployments 管理页及其模拟同步状态。Terminal Logo 继续由 Settings → Branding 管理，不与广告混为一项配置。

## 3. 统一业务概念

| 名称 | 本文含义 |
| --- | --- |
| 广告规则（Advertising Campaign） | 一套有名称的广告配置，包含展示模式、按顺序播放的素材清单，以及门店和／或单台终端目标。一条规则可覆盖多台终端 |
| 素材（Media） | 可被规则引用的图片或视频文件。素材本身不是终端配置 |
| 播放列表（Playlist） | 一条规则中按顺序排列的素材及播放时长设置；同一列表只能全部为图片或全部为视频 |
| 门店目标（Advertising Store Target） | 持续覆盖该门店当前及未来符合条件的无人值守终端，不是选中当时终端的一次性快照 |
| 当前广告分配（Advertising Target Assignment） | 平台当前把哪条已发布、未停止的规则分配给某台终端；不代表设备已下载或正在播放 |
| 目标冲突（Advertising Target Conflict） | 一条规则希望覆盖的终端或门店，已被另一条已发布、未停止的规则占用 |
| 已发布版本 | 某次发布确认的完整配置，包括素材清单及其元数据；编辑中的内容不能直接改变它 |

“终端已配置广告”在本文中指存在当前广告分配，**不指历史上曾经配置过，也不包括仅在草稿中被选中**。

Terminal Name 与 S/N 分开显示。名称可为空；为空时不显示名称，不用序列号或占位文字补成名称。S/N 只出现在明确标注的位置。

## 4. 页面入口与客户操作流程

### 4.1 Advertising 管理页

入口位于主导航 Advertising，包含 Campaigns 和 Media Library 两个页签。

Campaigns 列表提供名称搜索及 Draft／Published／Stopped 状态筛选。每行展示 Campaign 名称、Display Mode、Playlist 数量、Targets、Status、Actions。状态展示已发布／已停止及版本；后续门店变化导致的冲突额外显示 Target conflict，不把它当成一种新的发布状态。

操作规则如下：

| 操作 | 行为 |
| --- | --- |
| New Campaign | 新建未发布规则；一般入口默认无目标，从终端上下文进入时可预选该终端，但仍受占用校验约束 |
| 点击名称或 Edit | 打开该规则编辑器；是否修改由用户决定 |
| Duplicate | 复制可编辑配置，产生独立未发布规则，不复制发布版本或占用关系；一般入口清空目标，终端上下文可预选当前终端 |
| Stop Campaign | 仅已发布且未停止的规则提供；确认后停止该规则的全部覆盖，释放占用并停止未来门店成员自动纳入 |

列表不新增独立 Campaign Preview 操作。已有规则的编辑器保留内嵌终端预览。

### 4.2 无人值守终端详情

Advertising Tab 位于 Alerts 右侧，保持现有 Basic Information 布局。

有当前广告分配时，展示该规则**已发布版本**的名称、展示模式、素材缩略图与数量，以及配置来源：

- Direct terminal assignment：直接指定该终端。
- Store · 门店名称：通过所属门店覆盖。

点击素材直接预览，保持素材自身比例；视频预览提供控制条并默认静音。关闭预览停止并释放播放。素材无法加载时显示不可用及处理说明，不显示成“未配置广告”。

**View Campaign 必须进入按当前终端筛选的 Campaigns 列表，不得自动进入编辑器。** 保留终端名称、明确标注的 S/N、Terminal Details 和 All Terminals 入口。列表仍可搜索、按状态筛选，客户自行点击 Edit 后才进入编辑。Terminal Details 返回原终端的 Advertising Tab；All Terminals 退出终端筛选。

终端详情只展示当前分配，而进入后的 Campaigns 列表可以包含与当前终端相关的草稿、已发布和已停止规则。不能把“列表里有记录”作为“终端当前已配置”的判断依据。

无当前分配时显示 No advertising configured，并提供 Manage Advertising，进入当前终端的 Campaigns 列表。草稿和已停止规则不作为当前广告展示。数据读取失败必须显示加载失败及重试入口，不能伪装为空状态。

### 4.3 共享规则修改

从一台终端进入的仍是同一条共享规则，不会自动复制成该终端专用规则。修改后重新发布，会影响该规则发布目标范围内的所有终端。

从终端上下文进入编辑时，需显示共享目标数量及影响说明。例如一条规则覆盖 20 台终端，从其中一台进入修改图片，也是在修改这条覆盖 20 台的规则。若只想让一台使用不同规则，必须先从原规则覆盖范围中释放该终端，再配置另一条；门店继承情形见第 6 节，不能在终端详情直接覆盖门店规则。

## 5. 创建、编辑与发布

### 5.1 配置项

| 配置项 | 要求 |
| --- | --- |
| Name | 必填；当前页面长度上限为 80 个字符。不新增 Advertiser 字段 |
| Display Mode | Idle screen 或 Full screen，一条规则选择一种模式 |
| Playlist | 从素材库选择、调整顺序、移除素材；首次加入的素材类型决定当前列表类型 |
| 图片时长 | 每张 3–120 秒，整数，默认 8 秒 |
| 视频时长 | 按视频自然时长完整播放，不按图片时长截断 |
| Full-screen idle time | 仅全屏模式配置，5–600 秒，整数，默认 30 秒 |
| Image fit | Fit entire image 保持完整比例；Fill area 允许裁切填满，不拉伸变形 |
| Targets | 可混合选择门店与单台终端，按第 6 节校验 |

默认新建为 Idle screen、顺序循环、Fit entire image；从一般入口新建时播放列表和目标为空。无开始／结束排期，发布后持续配置，直到停止或被该规则的新版本替换。

### 5.2 状态与允许操作

| 状态 | 是否占用目标 | 编辑与保存 | 后续操作 |
| --- | --- | --- | --- |
| Draft，尚未首次发布 | 否 | 可保存不完整草稿；至少填写名称，已选择的目标必须有效 | 完成校验后首次发布；可复制 |
| Published，已发布未停止 | 是，依据已发布版本 | 允许编辑，但不再提供 Save Draft；编辑中内容不改变当前分配 | Review & Publish 产生新版本；可停止、复制 |
| Stopped，曾发布后停止 | 否，不再持续覆盖门店新成员 | 保留可编辑配置及历史发布信息；不提供 Save Draft | 重新完整校验后发布为新版本；可复制 |

取消编辑或离开时保护未保存内容；用户明确放弃后才丢弃。未保存修改不进入终端详情，也不改变其他规则的占用判断。

### 5.3 发布流程

1. 点击 Review & Publish，检查名称、模式、素材有效性、类型一致性、图片时长、全屏等待时间及目标有效性。
2. 至少选择一个有效门店或单台终端。允许选择当前零终端的门店，因此当前覆盖终端数为 0 不必然禁止发布。
3. 检查其他已发布、未停止规则产生的门店和终端占用；有冲突则阻止发布，说明冲突对象、原因及处理方式。
4. 展示确认摘要：规则名称、模式、下一版本、门店／单台目标数量、去重后的当前覆盖终端数和素材数量。取消确认不产生发布或占用变化。
5. 最终确认时重新校验最新数据，不能只信任打开编辑器或确认框时的检查结果。
6. 成功后保存发布版本，原子更新目标分配并返回列表；失败不得显示成功，也不得留下部分新分配。保留输入，定位错误提示。

服务端须保证重复提交、多人同时编辑和同时争用目标时，仍符合唯一分配原则。版本并发策略由研发设计并在评审时确认。

## 6. 核心规则：防止重复配置与相互覆盖

### 6.1 一台终端同一时刻最多一条当前规则

**BR-01：终端已经被规则 A 的已发布、未停止版本占用时，不能再新增到规则 B 的有效配置。** 不允许“最后发布的覆盖之前的”，也不允许空闲屏和全屏各配置一条来绕过限制。一个规则内可以有多个同类型素材，不等于多条广告规则。

**BR-02：同一规则编辑自身不构成冲突。** 当前规则已覆盖的对象需与“被其他规则占用”区分，允许继续维护。重复点击同一终端，或同一规则同时通过门店和单台覆盖同一终端，只计算一次。

**BR-03：草稿不占用目标。** 两条未发布草稿可以含有同一终端；其中一条发布成功后，另一条必须在重新选择及发布时受到占用限制。不能因为曾经在草稿或历史规则中出现过，就永久禁止终端重新配置。

### 6.2 选择前即展示限制

**BR-04：目标列表在选择前展示 Assignment。** 终端显示占用它的规则名称；门店显示整店占用，或当前被其他规则占用的终端数量及对应规则名称。应区分本规则、其他规则和未占用。

**BR-05：已被其他规则占用的对象禁止新增选择，全选跳过不可选项。** 不能先让用户选完全部目标，再只在提交时笼统报错。

**BR-06：旧选择发生冲突后，仍允许取消。** 例如先保存草稿，之后目标被另一条规则占用：再次打开时保留已选内容并展示冲突，用户可取消勾选或在 Selected 中移除，不能把冲突行完全锁死。

**BR-07：提交仍须再次校验。** 前端置灰只是操作提示，后端最终发布必须检查唯一性。若发布范围中有一个冲突目标，本次发布整体失败，不能悄悄跳过该终端后报告整条规则发布成功。

### 6.3 门店目标是持续覆盖

**BR-08：门店目标覆盖当前及未来符合条件的成员。** 终端新增或迁入时，自动尝试继承门店规则；迁出后退出该门店覆盖。若另有有效单台目标，则按其直接指定关系判断，不因为迁店一概清除。

**BR-09：整店被规则 A 占用后，规则 B 不能再次选择该门店。** 即使该门店暂时没有终端，整店占用仍成立。只要有一台当前成员被另一条规则占用，也不能新增选择整个门店来覆盖它；选择器应显示部分占用情况。用户可以切换到 Terminals，明确选择该门店中其余未占用终端，但这不建立整店持续覆盖。

**BR-10：同一规则内门店覆盖优先做去重。** 选择门店后，其覆盖终端显示 Included by store；重复的单台选择会被合并移除。取消门店后，不自动恢复之前已合并的单台选择。

当前没有“整店选择后排除某一台”的能力。如果要把该门店中的一台交给另一条规则，应先调整原规则目标，使其不再整店覆盖该终端；必要时改为明确选择其余终端，再给该终端配置其他规则。不能用单台新规则直接覆盖整店规则。

### 6.4 发布后的成员变化

**BR-11：门店变化导致的新冲突不得抢占仍然有效的既有归属。** 例如规则 A 直接指定了终端 T，之后 T 迁入规则 B 覆盖的门店：A 仍覆盖 T，因此 T 保留 A；B 对 T 的新增覆盖未生效，显示 Target conflict，其他无冲突终端继续按各自当前分配运行。

如果 A 仅通过旧门店覆盖 T，且没有直接指定 T，那么迁出旧门店后 A 的覆盖已经失效，应先释放旧归属，再按新门店范围分配。不能把“保留原归属”理解为无论终端是否仍在原规则范围内都保留旧广告。

该情形不同于“用户正在发布一条带冲突的新版本”：新版本发布必须整体拦截；已发布规则因后续门店变化遇到冲突时，不停止其原有无冲突覆盖。

**BR-12：停止或缩小覆盖后重新计算归属。** 停止 A，或重新发布 A 并使 T 不再处于其任何目标范围，才能释放 T。释放后，如果另一条已发布、未停止规则 B 的门店范围仍然覆盖 T，且没有其他阻挡，系统应在重新计算时自动把 T 分配给 B，并清除对应冲突；否则恢复未配置，之后才能选择新的规则。缩小 A 的范围只取消已移除范围的覆盖，保留的门店目标仍继续纳入未来成员。

停止是整条规则的操作，会影响其全部目标，不能把 Stop Campaign 解释为“只停当前查看的终端”。停止后保留规则用于查看、复制和重新发布。

### 6.5 规则示例

| 场景 | 必须得到的结果 |
| --- | --- |
| T 已被已发布 A 占用，B 想单独选 T | 显示 A 的占用，禁止新增选择；绕过界面提交也失败 |
| A 是空闲屏广告，B 是全屏视频，也要选 T | 仍然冲突，不按模式拆成两个占用名额 |
| A、B 都是草稿且包含 T | 草稿可以存在；先发布成功的一条获得占用，另一条不能再发布覆盖 T |
| A 正在编辑自己已覆盖的 T | 不报“被自己占用”的冲突；新版本发布后仍属于 A |
| A 已覆盖门店 S，S 暂无终端 | B 不能选择 S；以后 S 新增未占用终端时由 A 覆盖 |
| S 有 10 台终端，其中 2 台已属于 A，B 想选择整个 S | 显示已有 2 台占用及 A 的名称，禁止新增整店选择，不自动跳过 2 台发布 |
| A 同时选 S 和 S 内的 T | 覆盖终端数不重复；T 由门店包含，不保留多份分配 |
| 被 A 直接指定的 T 迁入 B 的门店 | A 的覆盖仍有效，保留 A，B 提示冲突；不得静默改为 B |
| T 只通过旧门店属于 A，迁入 B 的门店 | 旧门店覆盖失效，释放 A，再按新门店覆盖分配 B |
| 停止 A，但 T 仍处于已发布、未停止 B 的门店范围 | 释放 A 后自动归属 B 并清除对应冲突；停止 A 不等于保证 T 最终无广告 |
| 某规则只修改素材，重新发布 | 目标继续由该规则覆盖，已发布素材切换到新版本，不产生第二条分配 |

## 7. 展示模式与支付优先

| 项目 | Idle-screen Advertising | Full-screen Advertising |
| --- | --- | --- |
| 内容 | 仅图片轮播 | 图片轮播或视频列表，二选一 |
| 展示区域 | 待支付页面的中央内容区 | 整个广告显示区域 |
| 支付页面元素 | 保留终端 S/N、时间、支付方式、Terminal Logo、商户页脚 | 退出广告后恢复支付页面 |
| 启动条件 | 终端处于待支付／空闲状态 | 达到配置的空闲等待时间 |
| 退出条件 | 支付流程优先 | 点击屏幕返回支付流程；支付请求优先 |
| 声音 | 无 | 视频始终静音 |

播放列表固定按顺序循环。图片与视频不能混排；已有视频时不能直接切到 Idle screen，需先清空不兼容的视频。编辑器只允许添加兼容素材。

终端预览用于帮助用户判断画面比例、裁切和列表效果。当前提供 Q3V (UPT) 与 Q3min 预览，切换预览机型不改变规则目标，不代表所有被选终端都已通过该机型的兼容性认证。

素材预览只显示原素材；终端预览显示编辑中的配置和设备屏幕效果。两者均不是实际终端回传画面。浏览器预览的缺失／失败素材回退到默认支付画面；真实设备的文件失败、更新中断及离线回退策略还需按第 12 节明确并联调验证，不能用网页演示代替。

## 8. 素材库与目标选择体验

### 8.1 Media Library

- 支持素材名称搜索及图片／视频筛选，显示名称、尺寸、文件大小和类型。
- 上传支持 JPG、PNG、WebP，单文件不超过 10 MB；MP4、WebM，单文件不超过 50 MB。正式端需再次校验文件类型、大小和可解码性。
- Media name 可选；未填写时使用完整文件名。选择文件不能自动覆盖用户已填名称。不增加 Advertiser 字段。
- 点击封面或名称预览，图片保持原比例，视频提供播放控制且默认静音。关闭后停止播放。
- 上传失败说明原因并保留可保留的输入，不能显示上传成功。只在文件和元数据均可用后开放引用。
- 删除前确认；被任何已保存草稿或已发布版本引用的素材不能删除，避免破坏既有规则。已停止规则保留的发布版本引用也需检查。
- 示例中的 SVG 是内置演示资源，不因此扩大用户上传格式范围。浏览器可播放 MP4／WebM 也不代表真实终端支持全部编码。

### 8.2 Targets

Stores、Terminals、Selected 三个子页签保留。Agent、Merchant、Store 级联筛选支持点选、输入搜索和键盘操作；变更上级筛选可以重置下级筛选，但不能丢弃已选目标。

全选仅作用于当前可见且可选的行。Selected 集中展示全部已选门店与单台终端，支持搜索、逐项移除和 Clear all；Clear all 清除全部选择，不只清除搜索结果。

Selected 数量是“门店条目数＋单台终端条目数”；实际覆盖数是去重后的当前终端数。两个数字不能混用。不可用或已冲突的旧目标仍要可见、可移除。

### 8.3 页面一致性与错误处理

复用现有 Portal 字体、共享导航和组件样式。列表表头保持 34px、浅灰背景、11px 字体；表单按钮 40px，列表行操作 36px。终端详情的主 Tab 选中下划线为白色；View Campaign 交互状态保持白色文字与图标，无蓝色链接下划线。

保存、发布、冲突等错误应在实际滚动容器内定位并聚焦，不能被固定栏遮住。错误要指出对象、原因及可执行处理方式。禁止自动清空用户输入、默默覆盖其他规则或把失败当作空数据。

## 9. 数据与研发必须保证的结果

无需照搬原型的浏览器存储结构，但以下对象及关联必须能够被正式系统表达：

| 对象 | 必须保留的信息与约束 |
| --- | --- |
| 广告规则 | 稳定标识、名称、发布状态、可编辑配置、最近发布版本及修改信息；名称不作为关联主键 |
| 发布版本 | 版本号、发布时间、完整展示配置、素材顺序／时长、素材版本或不可变引用、发布目标范围 |
| 素材 | 稳定标识、名称、类型、尺寸、大小、视频时长和可访问文件；被引用文件不能无声替换 |
| 门店目标 | 稳定门店标识和持续覆盖关系，零终端时仍有独占意义 |
| 单台目标 | 稳定终端身份，对外显示规范 S/N；名称变化不能影响关联 |
| 当前分配 | 终端与唯一当前规则／发布版本的关系，可解释来自单台指定还是门店覆盖 |
| 冲突信息 | 请求覆盖的规则、涉及终端或门店、已有归属；供列表提示和发布错误使用 |

正式服务端必须统一执行唯一占用检查、版本发布、停止释放和成员变化重算。冲突校验与分配写入必须具有事务一致性；不能靠前端缓存或“先查询再单独写入”的竞态流程保证唯一性。

一次发布失败不得部分覆盖目标；一次成功响应必须能被随后列表和终端详情查询到。重复确认发布不得意外创建多个版本；旧编辑页不得在无提示情况下覆盖他人已发布的新版本。幂等和并发控制的具体方案由研发提出。

## 10. 研发工作拆分与交付边界

| 工作项 | 研发需要交付什么 | 当前原型不能证明什么 |
| --- | --- | --- |
| Portal 前端 | 两个页面及上述状态、筛选、预览、跳转、返回、错误反馈；接真实接口后维持交互 | 不能用页面已显示成功代替服务端成功 |
| Campaign 服务 | 草稿、复制、发布版本、停止、查询、终端上下文查询与并发控制 | localStorage 不是共享数据源或事务机制 |
| 目标与占用服务 | 门店／终端查询、占用详情、唯一校验、动态覆盖、冲突保留及释放重算 | 原型目录加载时重算不等于生产成员事件已经接入 |
| 素材服务 | 上传、校验、持久文件存储、访问控制、元数据、引用保护与删除 | IndexedDB 中的文件不能直接作为终端分发资源 |
| 正式权限接入 | 当前用户的数据范围、查看／编辑／发布／停止／删除授权，接口逐项校验 | 角色模拟器和隐藏菜单不构成安全控制 |
| 设备端接入评估与实现 | 明确终端如何获得配置和素材、如何更新／停止、如何保证支付优先，并完成指定机型联调 | Published 只表示平台发布，不能证明下发、下载或实际播放成功 |
| 联调与验收 | 按第 11 节测试业务规则；针对第 12 节决议补齐设备端验收 | 浏览器预览、前端测试通过不等于终端实机验收通过 |

“平台已发布”和“终端已执行”是不同结果。本期页面不增加 Deployments 和设备同步状态；正式设备链路的内部确认、失败处理及可观测性仍须由研发设计，不能因为不展示状态就省略可靠性处理。是否增加客户可见的设备执行状态，需另行确认。

| AC-01 | 打开无人值守终端详情 | Advertising 在 Alerts 右侧，原有基础信息布局不变 |

| AC-03 | 点击 View Campaign | 打开当前终端筛选列表，编辑器未自动打开；列表 Edit 可由用户自行选择 |

| AC-05 | 终端仅存在草稿或历史停止规则 | 详情显示未配置；管理列表仍可展示相关记录 |
| AC-06 | 新建规则仅填写有效名称后保存草稿 | 可保存，无目标占用，不要求已完成素材和目标配置 |
| AC-07 | 已发布或已停止规则进入编辑 | 无 Save Draft；必须 Review & Publish，成功后形成新版本 |
| AC-08 | 图片时长 2、121 或小数；全屏等待 4、601 或小数 | 发布被拒绝，错误定位到可见位置；合法边界值可通过 |
| AC-09 | 添加混合类型素材，或带视频切到空闲屏 | 阻止不兼容配置，说明原因；顺序调整后按新顺序预览 |
| AC-10 | T 已属于已发布 A，B 选择 T 或尝试换展示模式重复配置 | 显示占用并禁止新增选择；服务端发布同样拒绝 |
| AC-11 | 批量全选包含被其他规则占用的对象 | 全选跳过冲突项，已有合法选择保留 |
| AC-12 | 已存草稿的目标后被另一规则占用 | 冲突选择仍能看见和移除；再次发布被拦截 |
| AC-13 | 同一规则编辑自身，门店和单台重复覆盖 | 不自冲突，终端只计一次，不产生重复分配 |
| AC-14 | 发布目标中一部分发生冲突 | 整次新发布失败，原有分配保持；不部分发布、不报告成功 |
| AC-15 | 两个请求同时争用同一终端或同一空门店 | 最多一条规则获得占用，另一请求明确失败，无短暂双归属 |
| AC-16 | 规则 A 发布覆盖零终端门店，B 再选同店 | A 可发布；B 被拦截；该店新增合格未占用终端后继承 A |
| AC-17 | 终端迁出门店／另有直接指定 | 只移除失效门店覆盖；仍符合直接指定时保留对应规则 |
| AC-18 | 被 A 直接指定的终端迁入 B 覆盖门店 | A 仍覆盖它，原归属保留，B 显示冲突，其他终端不受影响；仅来自旧门店的失效归属不保留 |
| AC-19 | 停止 A 或缩小其发布范围 | 正确释放不再覆盖的目标；停止 A 取消其全部未来覆盖，缩小范围不影响保留门店的未来覆盖；有仍有效的 B 门店范围且无其他阻挡时自动归属 B 并清除冲突 |
| AC-20 | 重新发布已停止规则时目标被其他规则占用 | 不因曾拥有目标而直接恢复；完整校验并拦截冲突 |
| AC-21 | 修改共享规则素材并发布 | 按整条规则范围更新；不能只改变从其进入编辑的终端 |
| AC-22 | 上传超限／错误格式／不可解码文件 | 明确失败；不产生可正常引用的伪成功素材 |
| AC-23 | 删除被草稿、发布版本或停止规则版本引用的素材 | 拒绝删除并说明引用原因；未引用素材确认后可删除 |
| AC-24 | 素材预览、关闭、媒体加载失败 | 比例正确，视频静音且可控制，关闭释放播放，失败有说明 |
| AC-25 | 保存／发布服务失败或终端详情加载失败 | 无成功提示、无意外占用变化；保留输入；不把加载失败当未配置 |
| AC-26 | 无权限用户直接访问页面或构造接口请求 | 不能越权查看素材、规则和目标，不能越权执行修改 |
| AC-27 | 改变筛选、搜索已选项、逐项移除、清空选择 | 筛选不丢选择，所选数量和覆盖数各自正确，全选遵循可选范围 |
| AC-28 | 终端没有名称、名称被修改或存在相同名称 | 关联仍按稳定终端身份；不伪造名称或把 S/N 拼成名称 |
| AC-29 | 检查三个详情页主 Tab 和 View Campaign 交互 | 主 Tab 白色下划线；按钮文字／图标保持白色，无蓝色链接下划线 |

AC-01～29 覆盖平台侧需求。设备端还需在明确支持范围后，实机验收支付请求优先、触屏退出、静音、比例与裁切、列表循环、版本更新和停止执行；离线与失败场景按评审结论补充，不能以网页预览替代。

以下内容不能从两个原型页面推断为已具备能力。可先开展已明确的 Portal 与规则服务设计，但设备交付承诺和相关开发估算必须包含这些确认项。

| 待确认项 | 需要产出的明确结论 | 建议参与方 |

| 历史版本与素材保留 | 是否要求可查历史版本或回滚，保留周期与空间回收方式；不能直接删除仍被有效引用的文件 | 产品、后端 |
