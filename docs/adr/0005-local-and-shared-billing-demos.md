# Billing supports both static local demos and shared demos

The authoring workflow must work directly in VS Code Live Server and on static hosting, while external payment demonstrations also need shared cross-device state. Local Billing Demo and Shared Billing Demo therefore coexist explicitly, using the same payment rules and separate persistence; this qualifies ADR 0003's shared-only requirement without weakening the shared bill's authoritative state or duplicate-payment boundary. A missing API on a new static site, or an initially unconfigured hosted site, permits local demo mode; a configured or previously recognized shared service must not silently fall back after a failure, and local snapshots never become shared payment results.

Shared deployment uses Vercel Functions and private Vercel Blob with uncached reads and conditional writes, keeping the small prototype on Vercel while detecting concurrent payment changes. Shared management requires a secret-derived expiring session, public links grant access to one bill, and scheduled simulation uses a daily task plus due-date processing on reads; local scheduling advances when the demo is open. The existing Vite/SQLite development service remains available, existing data is retained, and local demo records are not automatically uploaded to shared storage.
