# Resume overdue collection at the next normal installment date

On 2026-09-09 the user confirmed that a failed installment must be retried automatically at the next normal installment collection date, while retaining platform-operations-confirmed Retry Payment. Each collection round starts at the oldest due unpaid installment, settles each installment separately through the current installment, and stops immediately at the first failure; no extra automatic retries occur between normal collection dates. This replaces the no-automatic-retry restriction in ADR 0002 and ADR 0007 and the payer-only retry rule in ADR 0007, avoiding indefinite blocking after one failure without introducing continuous collection attempts. Original contract dates, the fixed installment limit, existing authorization and permanent collection-stop rules remain applicable. The demo now applies this rule through the shared domain collection function, persisting schedule rounds and honoring same-day manual failure suppression.

The user further confirmed automatic collection at 09:00 UTC on each normal installment due date. Manual and automatic attempts for an installment are mutually exclusive; a manual failure suppresses further automatic attempts for that UTC day. After the final scheduled installment date, outstanding installments remain payable only by platform-operations-confirmed retry, with no new automatic dates or extension of the contract. Each collection round that actually fails produces one failure notification to the payer or authorization email; unauthorized overdue bills do not produce overdue reminder emails.

The user scoped the implementation to a demonstration prototype. Local browser synchronization coalesces missed wake-ups to the latest eligible original schedule and does not replay older failed rounds; no payment gateway or actual email delivery is enabled.

The user clarified that every normal installment date continues automatic catch-up even after an earlier catch-up failure. Retry Payment is an operations-only compensating action using the retained card, available from Billing Overview for both merchant and standalone bills, including debt remaining after the final scheduled date. Payer pages and failure emails provide status viewing only, with no retry or card replacement. First-payment failure is outside this change.
