# Resume overdue collection at the next normal installment date

On 2026-09-09 the user confirmed that a failed installment must be retried automatically at the next normal installment collection date, while retaining payer-confirmed Retry Payment. Each collection round starts at the oldest due unpaid installment, settles each installment separately through the current installment, and stops immediately at the first failure; no extra automatic retries occur between normal collection dates. This replaces only the no-automatic-retry restriction in ADR 0002 and ADR 0007, avoiding indefinite blocking after one failure without introducing continuous collection attempts. Original contract dates, the fixed installment limit, existing authorization and permanent collection-stop rules remain applicable. Current prototype scheduling still blocks on Failed installments and must be changed before it conforms to this decision.

The user further confirmed automatic collection at 09:00 UTC on each normal installment due date. Manual and automatic attempts for an installment are mutually exclusive; a manual failure suppresses further automatic attempts for that UTC day. After the final scheduled installment date, outstanding installments remain payable only by payer-confirmed retry, with no new automatic dates or extension of the contract. Each collection round that actually fails produces one failure notification to the payer or authorization email; unauthorized overdue bills do not produce overdue reminder emails.
