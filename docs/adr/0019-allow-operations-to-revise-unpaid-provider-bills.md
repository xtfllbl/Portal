# 运维可修改尚未支付的服务商账单，发布不锁定金额

2026-10-28 确认：系统根据设备事件计算服务商季度账单初稿，运维拥有收费台数、激活费和各月服务费类目的最终调整权限；首次核对后发布，但只要账单尚未支付，发布后仍保留修改能力，已支付账单锁定。该决定取代“发布即锁定”的建议，以支持运维在收款前修正最终应收；单张账单调整不改变设备历史事实，也不自动改变服务商后续的收费标准。

服务商及付款页只展示已发布的最终收费项目、数量、金额和必要费用说明；系统原始试算、内部修改记录及原始金额对比仅运维可见，记录修改人、时间和原因。事件详情须保留真实含义，不能因账单按 18 台收费就把实际 20 台的激活事件改成 18 台；对外费用说明应解释必要的计费数量或金额差异，不暴露内部操作记录。

为实现这一规则，修改应保留同一账单身份和已有支付链接，访问同一链接时展示当前有效的已发布金额。支付提交必须重新校验付款人确认的收费内容及金额；若账单已被修改，应先展示新账单并要求重新确认，不能直接按新金额扣款，也不能按旧金额结清新账单。支付请求一旦提交且结果未明，账单修改与新支付须等待结果确认；失败后恢复未付可修改状态，成功则保存该次实付对应的账单内容并锁定，超时不直接当成失败。

上述支付并发保护是支持“未支付可修改”的实现约束，尚未在现有原型中实现。服务商账单的修订规则不改变现有商户固定期合同的金额、授权或延期规则。
