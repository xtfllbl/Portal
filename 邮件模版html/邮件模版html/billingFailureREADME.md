# Billing 失败通知与邮件事件预览

本次为演示原型，没有真实扣款或邮件投递。所有新邮件基于账单事件快照渲染，包含主题、HTML和纯文本；付款和邀请收件邮箱分别保存，不因后续付款改变历史收据。

在 44 Billing Overview → 账单更多菜单 → **View emails** 查看该账单已发生的邀请、每笔成功收据和每轮失败通知，可切换 HTML / Plain Text。旧记录不补造历史邮件；可以在当前原型执行 Send Link 或付款/Retry 产生新的模拟事件。

静态入口：[billingFailureSamples.html](billingFailureSamples.html)，首页邮件目录也增加了“扣款失败与补扣”。`billingPaymentFailure.html` 是部分补扣失败场景的可直接打开模板预览；可复用渲染逻辑在 `../../scripts/billing-emails.js`。

八种新增场景：一次性失败、分期首期失败、计划扣款失败、部分补扣成功后失败、最后计划日失败（Standalone/eSIM 0 MB）、单期补扣成功快照、多期积欠邀请、停止后的在途成功收据。每种都有 `.json / .html / .txt / .subject.txt`。

从项目根目录运行 `node scripts/render-billing-email-samples.mjs` 可复现全部新样例。生成器只写样例文件，不修改浏览器账单、不发送邮件。

失败通知规则：

- 只有明确发生的支付失败产生通知，每轮一封；未授权逾期、表单错误、重复请求或无应付期任务不产生失败通知。
- 展示失败期和金额、本轮已成功期、到期未付期及合计；不得把未尝试期当作拒付，也不得把本轮部分成功说成完全没扣款。
- 下个正常分期日 09:00 UTC 从最早欠款期逐笔补扣至当期，失败即停；当天手动失败后跳过该日自动任务，不能次日补执行这次被禁止的任务。
- 没有后续正常计划日时提示联系平台人工处理，不虚构下一自动日期。
- 已授权失败按钮为 View Payment Status，进入43只读查看状态，无Retry或换卡入口；人工Retry仅在44平台端。未授权一次性失败样例保留View Bill & Pay，首次失败流程不在本次调整范围。
- 停止收款将未投递失败事件标为 Suppressed。预览已停止账单时不显示可付款操作，也不另外生成停止通知。
- 成功收据每次只展示该笔实际成功金额和对应期号，历史事件快照保持不变。

静态样例链接采用 example.com 域名，不是实际付款入口；本地品牌图片用于预览。44运行时邮件链接使用当前本地账单URL。正式渠道、真实寄信和真实邮件客户端兼容性不属于本次演示范围。
